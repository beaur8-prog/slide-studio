# PPTX 저장 통일과 문서 폴더 기억

2026-10-21. 다음 배포용 소스 변경이며 공개 1.6.5 설치 파일과 리토스 공유 문서는 갱신하지 않았다.

- 파일 메뉴·빠른 저장·상단 버튼·명령 검색·Ctrl/⌘+S·OS 파일 메뉴의 저장을 PPTX 하나로 통일했다. `.slide` 생성과 별도 PPTX 내보내기 메뉴를 제거했다. 저장은 기존처럼 파일 대화상자에서 위치와 이름을 선택한다.
- 기존 `.slide` 파일은 계속 열어 PPTX로 옮길 수 있다. 기기의 자동 저장·이전 문서 복원은 유지하며 기존 파일을 삭제하거나 자동 변환하지 않는다. PPTX 자체의 지원 범위는 [호환성 문서](../IO_NOTES.md)를 따른다.
- 네이티브 파일 읽기 또는 PPTX 저장에 성공한 폴더를 다음 열기·저장·PDF 대화상자의 시작 위치로 사용한다. 앱을 재실행해도 기억한다. 취소·읽기/쓰기 실패는 폴더를 바꾸지 않으며, PDF 출력도 현재 문서 폴더를 바꾸지 않는다. 폴더가 없어지면 Documents를 사용한다.
- 폴더 설정은 사용자 프로필의 `file-dialog-location.json`에만 보관한다. 설정 저장이 실패해도 실제 파일 저장은 성공하며 실행 중에는 새 폴더를 기억한다.
- PPTX 파일 형식만 저장하도록 브리지 입력을 제한했다. 사용자가 확장자를 생략하거나 다른 확장자를 입력하면 `.pptx`를 붙인다. 확장자를 붙인 실제 경로에 기존 파일이 있으면 덮어쓰기를 다시 확인한다. 저장 진행 중 반복 명령은 중복 실행하지 않는다.

## 검증

수정 전 검사에서 열기 대화상자의 `defaultPath`가 없음을 재현했다. 수정 후 관련 **29개 검사와 프로덕션 빌드가 통과**했다.

```sh
npx playwright test tests/native-save-folders.spec.ts tests/native-files.spec.ts tests/windows-ui.spec.ts tests/office-shell.spec.ts tests/presentation-isolation.spec.ts tests/pptx-save.spec.ts tests/presentation-ink.spec.ts tests/production.spec.ts
npm run build
```

검사 범위는 성공/취소/실패·재실행·삭제된 폴더·설정 쓰기 실패, 확장자 보완과 덮어쓰기 취소/승인, Windows 저장 단축키와 모든 저장 메뉴, 저장 중 중복 명령, 기존 `.slide`의 한글·노트를 PPTX로 저장 후 재가져오기, 발표 판서와 저장 격리 및 프로덕션 PPTX UI 저장이다.

Mac Electron 프로덕션 빌드를 별도 임시 프로필에서 실제로 두 번 실행했다. 네이티브 IPC를 통해 파일을 열고 PPTX/PDF를 디스크에 저장했으며 ZIP/PDF 읽기, 문서 폴더의 우선 사용·재실행 후 기억·PDF 출력 후 유지, 이전 `.slide` 원본 보존과 PPTX 변환을 확인했다. 파일 선택 창의 응답은 검사용으로 지정하고 전달된 네이티브 대화상자 옵션을 검사했다. 잠긴 화면에서 OS 대화상자를 직접 조작한 수동 검사는 아니다.

로컬 증거는 `qa/results/pptx-save/`의 `baseline.log`, `regression.log`, `build.log`, `native.json`, `native-pptx-save.png`에 있다. 사용 중인 앱·사용자 문서·프로필은 유지했다. 실제 사용 중인 Mac 앱 교체는 화면 잠금으로 보류했다.

## 첫 실행 빈 문서

아래는 1.6.6 배포 당시의 동작이다. 이후 요청의 ‘매 실행 빈 문서·최근 실제 파일 목록’ 수정은 이 문서 마지막에 별도로 기록한다.

자동 저장 문서가 없는 첫 실행은 예제 대신 텍스트·도형·노트가 없는 빈 슬라이드 한 장으로 시작한다. 기존 자동 저장 문서의 복원과 새 문서 메뉴의 예제 선택은 유지했다. 여러 장이 필요한 기존 검사는 `scripts/qa-open-sample.cjs`로 예제를 명시적으로 선택한다.

프로덕션 빌드가 통과했다. 스크롤·발표 격리/전체 화면·노트 크기 조절·한글/300장 편집·PPTX 가져오기/저장·화면 구성 검사 **23개가 통과**했고 Windows 네이티브 전체 화면 검사 한 개는 Mac에서 건너뛰었다. 별도 임시 프로필의 Mac Electron 앱을 세 번 실행하여 최초 빈 문서, 문서 이름·노트 편집의 재실행 후 복원, 예제 선택 및 기존 예제 복원을 확인했다. 로컬 증거는 `qa/results/blank-start/native.json`, `first-launch.png`, `restored-sample.png`, `regression/`에 있다. 공개 배포와 사용 중인 앱 교체는 하지 않았다.

## 매 실행 빈 문서와 실제 최근 파일 목록 — 다음 배포용 수정

사용자의 ‘처음 실행’을 설치 후 최초 실행으로 잘못 해석해 1.6.6에 남겼던 이전 문서 자동 복원을 수정했다. 프로그램 완전 종료 후 실행하거나 Mac 편집 창을 닫았다 다시 열면 빈 슬라이드 한 장으로 시작한다. 같은 창을 새로고침하는 경우에만 현재 편집 버퍼를 복원한다. 창마다 새 식별자를 전달하므로 이전 실행의 창 세션이 남아 있어도 복원하지 않는다.

‘내 프레젠테이션’을 내부 복사본 보관함에서 최근 실제 파일 목록으로 바꿨다. 네이티브 열기·저장에 성공한 실제 경로만 기록하고 정규화된 경로당 한 항목을 유지한다. 같은 이름이라도 다른 폴더에 있으면 별도 파일로 유지한다. 목록 표시 시 삭제·이동된 파일을 제외하며, 표시 후 삭제되었더라도 열기에 실패하면 다시 확인해 제거한다. 항목을 누르면 원본을 실제로 읽으며 내부 복사본으로 대체하지 않는다. 임의 경로가 아닌 등록된 파일 ID만 네이티브 재열기에 허용한다. 현재 창의 임시 편집 상태 하나 외에 파일별 문서 복사본을 추가로 저장하지 않는다.

구버전 자동 저장본은 원본 경로가 없어 실제 파일 목록으로 이관할 수 없다. 목록에서 제외하며 사용자 자료를 보호하기 위해 기존 내부 데이터를 자동 삭제하지 않는다. 실제 파일을 다시 열거나 PPTX로 저장하면 최근 파일에 등록된다. 웹 브라우저의 임시 편집 동작과 데스크톱의 실제 파일 목록을 구분한다.

빌드가 통과했다. 기존 관련 18개 검사와 신규 5개 검사를 확인했다. 신규 검사의 두 초기 실패는 Mac의 `/var` 경로가 실제 `/private/var`로 정규화되는 것을 예상값에 반영하지 않은 문제였으며 실제 정규화 경로로 비교하도록 고친 후 통과했다. 신규 검사는 삭제 직전의 목록 갱신·디스크 변경 재읽기·창 세션 변경·내부 복사본 목록 배제·문서별 사본 누적 방지·경로 정규화와 중복·동일 이름의 다른 폴더·최근 파일 정보 재읽기를 포함한다. 이전 이미지 페이로드 보관함 메모리 검사는 해당 보관함이 제거되어 파일 목록 검사로 대체했다.

별도 임시 프로필의 실제 Mac Electron 앱에서 반복 열기·PPTX 저장의 중복 방지, 완전 종료 후 빈 문서, 창 닫기 후 재열기, 원본 디스크 수정 재읽기 및 삭제 시 캐시로 열리지 않는 동작을 확인했다. 파일 대화상자와 임시 검증 프로필의 종료 확인창 응답은 검사용으로 지정했다. Mac 재활성화와 두 번째 실행 요청으로 창을 다시 여는 경로도 확인했다. 수정 완료 후 관련 모음 23개를 다시 실행해 모두 통과했다. 결과는 `qa/results/recent-files/`의 `regression.log`, `focused.log`, `final.log`, `build.log`, `native.json`, `native.log`에 있다. 이번 변경의 Windows/Linux 실제 설치판 검증과 공개 배포는 아직 하지 않았다.

## 매 실행 제목 슬라이드 — 2026-10-22 다음 배포용 수정

사용자 요청에 따라 새 창의 최초 문서를 완전히 빈 슬라이드 대신 ‘파일 → 새 프레젠테이션’의 제목 레이아웃으로 바꿨다. ‘프레젠테이션 제목’과 ‘이야기의 시작을 적어보세요’를 편집할 수 있는 한 장으로 시작한다. 기존 제목 레이아웃 생성기를 그대로 사용하며 이전 문서 자동 열기는 되살리지 않았다. 같은 창의 새로고침은 현재 편집 버퍼를 복원하고, 새 문서 메뉴에서는 빈 슬라이드도 선택할 수 있다.

최근 파일·같은 창 복원/새 창 시작·PPTX 저장·문서 폴더·도형 서식·화면 구성의 기존 검사 15개와 프로덕션 빌드가 통과했다. 제목 장의 장식 도형이 생겨도 도형 서식 검사가 실제로 삽입한 도형을 검사하도록 대상 선택을 조정했다.

Mac 패키지의 배포 소스 53개가 현재 빌드와 일치함을 확인했다. 별도 임시 프로필에서 최초 실행, 완전 종료 후 실행, Mac 재활성화 및 두 번째 실행 요청으로 창 다시 열기의 제목 슬라이드를 확인했다. 같은 창 새로고침 복원, 실제 최근 파일의 중복 방지·원본 변경 재읽기·삭제된 원본 배제, 네이티브 PPTX/PDF 저장과 폴더 기억도 통과했다. 대화상자 응답은 검사용으로 지정했다. 첫 화면 캡처를 확인했으며 증거는 `qa/results/title-slide-startup/`의 `regression.log`, `build.log`, `local-build.json`, `native-recents/`, `native-save/`에 있다. 공개 설치 파일과 리토스 문서는 갱신하지 않았다.
