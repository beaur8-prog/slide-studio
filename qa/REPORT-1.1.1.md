# Slide Studio PPTX·한글·성능 검증

검사일: 2026-10-17. 수정 버전: 1.1.1.

**공개 PPTX 5개의 열기와 한글 조합 자동 검사는 통과했습니다. 레이아웃 호환성은 미통과입니다.** 실제 글자 겹침·잘림, 표·일부 수식·그림 누락이 남아 있습니다. 파일을 열 수 있다는 결과가 원본을 온전히 재현한다는 뜻은 아닙니다.

## 자료와 열기 속도

CMU 강의 자료 4개와 동서대학교 공개 게시물의 한글 발표 자료 1개를 다운로드했습니다. 비교용 공개 PDF도 4개 받았습니다. PPTX는 총 **465장**, 1.89–191.80 MiB입니다. 아래 시간은 파일별 3회 측정의 중앙값이며, 다운로드 시간은 제외했습니다.

| 자료 | 크기 | 장수 | 편집 UI 표시 | 자동 저장 완료 |
| --- | ---: | ---: | ---: | ---: |
| [CMU lecture 1](samples/cmu-lecture-1.pptx) | 191.80 MiB | 70 | 1.57초 | 1.74초 |
| [CMU lecture 2](samples/cmu-lecture-2.pptx) | 11.72 MiB | 116 | 0.82초 | 1.31초 |
| [CMU lecture 3](samples/cmu-lecture-3.pptx) | 48.94 MiB | 151 | 0.91초 | 1.40초 |
| [CMU lecture 4](samples/cmu-lecture-4.pptx) | 14.84 MiB | 106 | 0.54초 | 0.96초 |
| [한글 실습 발표 자료](samples/dsu-korean.pptx) | 1.89 MiB | 22 | 0.21초 | 0.69초 |

15회 모두 예외 없이 열기·자동 저장·슬라이드 이동을 완료했으며 페이지 JavaScript 예외는 0건이었습니다. 슬라이드 이동 시간 중앙값은 파일에 따라 약 67–140ms였습니다. 클릭 자동화와 두 프레임 대기 시간이 포함되어 있습니다.

최대 파일은 약 201MB(191.80 MiB)이며 영상이 포함된 자료입니다. 지원하는 슬라이드 개체를 가져온 시간입니다. 영상 재생과 모든 포함 개체의 재현은 검사 통과 범위에 포함되지 않습니다. 기존 용량 상한에서는 이 파일을 거부했으며, 상한과 파일 전달 방식을 수정한 후 통과했습니다.

출처: [CMU 16-385 강의 자료](https://www.cs.cmu.edu/~16385/), [동서대학교 자료 게시물](https://cess.dsu.ac.kr/lifelong/index.php?idx=2039&mode=view&pCode=lecture). 개별 다운로드 URL·실제 바이트 수·SHA-256은 [sources.json](samples/sources.json)에 있습니다.

## 한글 입력 결과: 자동 검사 통과

Chromium 조합 엔진에 `ㅎ → 하 → 한`, `ㄱ → 그 → 글`을 입력하고 확정했습니다. 한영 혼용·숫자·받침·자모·문장부호·줄바꿈, 실행 취소/다시 실행, 자동 저장 후 새로고침, `.slide` 저장 형식 및 PPTX 왕복 변환에서 아래 문자열이 유지됐습니다.

```text
한글 입력 정상 — Hello 123
둘째 줄: ㄱㄴㄷ, 값·꽃·읽기
```

[한글 입력 결과 화면](results/final/korean-composition.png). 한글 내용의 입력·저장은 통과했지만, 가져온 기존 PPTX의 세로쓰기 레이아웃 문제는 위에서 별도로 확인했습니다.

Mac이 잠겨 있어 **macOS 한글 입력기에서 실제 키보드로 조합하는 검사와 설치 앱의 화면 조작은 이번에 하지 못했습니다.** 자동 조합 테스트를 실제 OS 입력기 검증으로 간주하지 않았습니다.

## 300장 편집 성능

앱 예제 4장을 복제한 텍스트·도형 중심의 300장 문서를 별도로 만들었습니다. 다운로드한 실제 자료와 구분되는 합성 스트레스 자료입니다. 마지막/첫 슬라이드로 이동한 후 텍스트를 편집하고 자동 저장했습니다.

| 측정 | 수정 전 | 최종 수정 후 |
| --- | ---: | ---: |
| 저장 문서 재열기 | 1.484초 | 1.436초 |
| 영문/숫자 10키 연속 입력 처리 | 0.824초 | 0.139초 |
| 편집 종료 → 저장됨 표시 | 0.917초 | 0.923초 |

각 값은 해당 자동 테스트의 단일 실행값으로, 통계적인 성능 보장은 아닙니다. 10키 입력은 지연 없이 자동 입력한 처리 시간이므로 사람의 타자 속도가 아닙니다. 300장에 모두 서로 다른 대형 이미지가 들어간 경우나 장시간 편집·메모리 누수는 이번 범위에 포함되지 않았습니다.

원시 기록: [수정 전](results/baseline/editor-metrics.json) · [최종](results/final/editor-metrics.json).

## 반영한 수정

- 바뀌지 않은 썸네일·인쇄용 슬라이드 렌더링을 재사용하고, 편집마다 전체 문서를 복제·문자열화하던 처리를 제거했습니다. 실행 취소/다시 실행 회귀 검사를 통과했습니다.
- 텍스트의 세로 정렬, 자동 줄바꿈 여부, 여백과 명시적인 자동 축소 비율을 레이아웃·마스터에서 상속하도록 수정했습니다.
- PPTX 대각 연결선의 길이와 회전각을 보존했습니다.
- 브라우저·데스크톱 파일 상한을 256 MiB로 맞추고, 네이티브 파일 전달에 바이트별 숫자 배열 대신 `Uint8Array`를 사용했습니다. 기존 압축 해제 크기·파트·이미지·개체 수 제한은 유지했습니다.

`npm test`: **10개 통과**. 한글·300장 편집, PPTX 왕복·상속·대각선·자동 축소, 입력 검증, 네이티브 바이트 전달 로직을 검사했습니다. 네이티브 전달 테스트는 Electron을 대체한 단위 검사이며 실제 파일 대화상자/IPC 왕복 검사는 아닙니다.

TypeScript·프로덕션 빌드·앱 패키징을 마쳤고, `/Applications/Slide Studio.app`을 **1.1.1**로 업데이트했습니다. 설치된 앱의 서명과 검증된 빌드의 내용 일치를 확인했습니다. [배포 ZIP](../release/Slide-Studio-mac-arm64.zip)도 갱신했습니다. 실행 중인 이전 버전은 앱을 다시 열어야 업데이트됩니다. 잠금 상태로 인해 업데이트 후 실제 앱 창은 확인하지 못했습니다.

## 측정 환경과 재현

Apple M4, macOS arm64, Google Chrome 155.0.8059.80, 격리된 headless 프로필, 1440×1000 화면에서 Vite 개발 서버의 편집기를 사용했습니다. 실제 Electron 설치 앱의 기동 시간이나 Finder 파일 선택 시간을 측정한 값은 아닙니다.

파일별 새 브라우저 컨텍스트에서 파서 단독 검사를 먼저 실행한 뒤, 실제 편집기의 파일 입력으로 열기·화면 생성·저장을 측정했습니다. 따라서 모듈과 파일 캐시가 준비된 상태이며 완전한 최초 기동 성능으로 볼 수 없습니다. 레이아웃은 동일한 슬라이드 렌더러의 인쇄 모드에서 모든 장을 표시해 검사했습니다.

```sh
python3 scripts/fetch-qa-samples.py
npm run dev
# 별도 터미널에서:
node scripts/qa-corpus.mjs final --repeat=3
npm test
npm run package
```

상세 원시 기록: [corpus.json](results/final/corpus.json), [요약 JSON](results/final/summary.json). 자료와 결과 파일은 로컬 `qa/`에 보관하고 Git과 배포 앱에서는 제외했습니다. 원본 공개 문서의 권리는 각 권리자에게 있습니다.
