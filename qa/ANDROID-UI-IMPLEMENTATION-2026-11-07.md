# Android 전용 UI 구현과 검증 — 2026-11-07

대상: 1.6.23 개발 소스. [Android UI 계획](ANDROID-UI-IMPROVEMENT-PLAN-2026-11-07.md)의 보기·탐색·발표와 기본 터치 편집을 반영했다. **이번 결과는 Android용 UI 소스이며, APK/AAB 배포나 Android 실기기 검증 완료를 의미하지 않는다.**

2026-11-08 후속 변경: 발표의 상시 탐색 바·페이지 이동 팝업과 하단 예약 공간을 제거하고, 전체 화면 표시·스와이프·필요할 때만 여는 도구로 바꿨다. 아래 기록은 최초 구현 시점의 결과이며, 현재 발표 동작은 [몰입형 발표 변경·검증 기록](ANDROID-IMMERSIVE-PRESENTATION-2026-11-08.md)을 따른다.

## 적용 조건과 데스크톱 격리

- Electron의 `window.desktop.platform`이 있으면 그 값을 우선한다. `darwin`, `win32`, `linux`에서는 Android UI를 활성화하지 않는다.
- 네이티브 실행 환경의 `Capacitor.getPlatform()`이 있으면 Android 여부를 판정한다. 브라우저에서는 UA Client Hints의 플랫폼과 Android UA를 확인한다.
- 화면 너비·터치 가능 여부·URL 쿼리만으로 Android UI가 켜지지 않는다. Android 태블릿의 데스크톱 UA는 네이티브 플랫폼 정보로 판정할 수 있다.
- 전용 CSS는 `.android-*` 또는 Android에서만 붙이는 `html[data-studio-platform="android"]` 아래로 제한한다.
- Windows·Mac·Linux의 리본, 화면 최소 너비, 마우스 클릭으로 발표 진행, 기본 노트 표시, 파일 저장과 복구 흐름은 기존 조건을 유지한다. 공유한 편집 명령의 기본 인수도 유지한다.

## 반영한 동작

### 시작·보기·탐색

- Android는 파일 열기와 새 프레젠테이션을 보여주는 시작 화면으로 연다. 문서를 연 뒤 시작 화면으로 돌아가도 현재 문서로 복귀할 수 있다.
- 가져온 문서는 보기 모드로 연다. 편집 캔버스를 마운트하지 않으며, 편집 명령·Undo/Redo·붙여넣기·조회 중 자동 저장을 차단한다.
- 원본 슬라이드 비율과 좌표를 유지하고 화면에 맞춘다. 두 손가락 확대/축소, 확대 상태의 이동, 두 번 탭 확대/맞춤, 버튼 확대/축소를 제공한다.
- 화면 맞춤 상태에서 좌우 스와이프는 한 장씩 이동한다. 확대 상태의 끌기는 페이지를 넘기지 않는다. 다중 터치·취소와 합성 클릭이 추가 페이지 이동을 만들지 않게 한다.
- 큰 이전/다음 버튼, 페이지 번호 직접 입력과 범위 검증, 전체 슬라이드 목록, 문서 검색, 읽기용 텍스트와 노트 패널을 제공한다.
- 축소판은 기존 공유 관찰기를 재사용해 보이는 영역 주변만 그린다. 151장 자료에서 전체 축소판 버튼을 유지하면서 실제 렌더링 수를 제한했다.
- 그림 디코딩이 실패하면 조용히 빈 화면으로 남기지 않고 안내한다. PPTX 가져오기 경고도 상세 패널에서 확인한다.

### 발표·미디어

- 현재 장에서 발표하며, 큰 이전/다음·페이지 이동·발표 도구·검은 화면·종료 버튼을 제공한다.
- 화면 탭은 발표 바 표시/숨김으로 사용한다. 스와이프와 명시적 이동 버튼이 페이지를 바꾸며, 링크·영상·오디오 조작은 페이지 이동에 섞이지 않는다.
- 길게 누르는 동안 레이저를 표시한다. 기존 레이저·펜·형광펜·지우개·Undo/Redo 메뉴에도 터치로 접근한다.
- 다중 터치·취소·화면 크기 변경 시 판서나 이동 후보를 정리한다. 발표 판서는 세션과 문서를 분리하고, 보관을 선택해야 문서의 편집 변경이 된다.
- 숨김 슬라이드는 일반 발표 진행에서 건너뛴다. 노트를 발표 화면에 표시하지 않으며 노트 표시 단축키도 Android에서는 적용하지 않는다.
- 가용 발표 영역을 직접 측정해 가로 화면에서도 슬라이드와 발표 바가 겹치지 않게 한다. 시스템 안전 여백을 반영한다.
- 기존 GIF·영상·오디오 렌더러를 재사용한다. Android에서 앱이 백그라운드가 되면 현재 미디어 재생을 정지한다. 실제 기기의 재생/복귀 정책은 별도 검증 대상이다.

### 기본 터치 편집과 태블릿

- 사용자가 편집을 선택하면 기존 편집 명령과 캔버스를 사용한다. 보기로 돌아갈 때 입력 중인 변경을 확정하고 선택·편집 패널을 정리한다.
- 작은 데스크톱 리본 대신 큰 편집 바와 펼치는 옵션을 제공한다. 글꼴·부분 서식·색상 적용·숫자 입력·Undo/Redo는 기존 검증된 명령을 공유한다.
- 텍스트·그림·기본 도형·표 삽입, 개체 선택 목록, 복사·복제·삭제, 도형 채우기와 선 두께/색, 기존 상세 서식 패널에 접근한다.
- 텍스트 상자의 자동 높이 계산으로 두 번 탭 위치가 달라지는 경우를 고려해 명시적인 `선택한 텍스트 편집` 버튼도 제공한다.
- 슬라이드 복사·붙여넣기·복제·삭제·앞뒤 이동과 앞/뒤 삽입 위치를 제공한다. 손가락으로 정밀하게 끄는 방법만 요구하지 않는다.
- 좁은 창에서는 축소판 패널을 접고, 서식 패널을 가용 너비 안에 표시한다. 넓은 태블릿 창에서는 기존 축소판을 함께 사용한다. 노트 조절 영역과 개체 조절점의 터치 판정 영역도 확대했다.

### 원본 공유·뒤로 가기·이전 편집 자료

- 원본 공유/다운로드는 재내보내기를 거치지 않고 가져온 파일 바이트를 사용한다. 공유 API가 없으면 원본 다운로드를 안내한다. 편집본 PPTX 저장은 별도 명령이다.
- 파일 선택 취소와 읽기 실패 후 다음 파일 요청이 막히지 않게 한다. 읽기 도중 중복 요청을 막고, 실패한 가져오기는 현재 문서와 원본 공유 자료를 바꾸지 않는다.
- Android 뒤로 가기와 Esc는 패널·입력·발표·편집 모드·시작 화면 순서로 처리한다. WebView 호스트용 취소 가능한 `slide-studio-android-back` 이벤트도 제공한다.
- 이전 임시 편집 문서를 자동으로 열지 않고, 시작 화면에서 `이어서 편집`을 선택하게 한다. 복원한 문서는 저장하지 않은 변경으로 보호한다.
- 다른 문서를 편집하기 전 이전 세션의 복구 원문을 데이터와 메타데이터 한 트랜잭션으로 보관한다. 기존 `current`를 삭제하거나 수정하지 않는 추가 보관 API다. 보관이 실패하면 새 편집 진입을 중지하고 이전 원문을 유지한다.
- 보관 자료는 Android 시작 화면/문서 메뉴에서 내려받을 수 있다. 기존 데스크톱 저장 경로는 이 추가 보관 API를 호출하지 않는다.

## Android 패키징 단계에 남긴 일

- Capacitor 등 실행 환경 확정과 APK/AAB 제작·서명·배포. 현재 UI는 플랫폼 감지를 준비했지만 Android 프로젝트를 생성한 결과가 아니다.
- Android 파일 URI·지속 접근 권한·최근 문서·외부 앱 열기/공유를 연결하는 네이티브 어댑터. 브라우저 File 입력과 Web Share/다운로드 검증을 SAF 전체 검증으로 계산하지 않는다.
- 독립 외부 화면 감지·출력과 본체의 발표자 노트/다음 장 분리. 현재 Android 발표 UI는 노트를 노출하지 않는 단일 화면/미러링용이다.
- 실제 키보드·한글 IME, TalkBack, 시스템 글자 크기, S Pen/손바닥, DeX/분할 화면, 실제 OS 뒤로 가기와 앱 강제 종료 복구.
- Android 기기의 코덱·자동 재생·백그라운드 복귀, 20분 사용과 10회 재열기 메모리, 약 192MiB 자료, p95 페이지 이동 목표 검증.
- 기본 도형 삽입과 주요 편집 진입점은 제공하지만 모든 데스크톱 고급 메뉴를 터치 UI로 옮긴 단계는 아니다. 고급 표/차트·정밀 다중 선택 등은 실기기 사용성 검사와 함께 확장한다.

공개 릴리스·다운로드 파일·리토스 문서는 갱신하지 않았다. 개발 버전 번호는 1.6.23을 유지한다.
