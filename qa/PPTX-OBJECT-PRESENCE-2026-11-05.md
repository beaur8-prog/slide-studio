# PPTX 표·그림 누락 검사 — 2026-11-05

개발 버전 1.6.23의 후속 수정이다. 공개 배포·GitHub Release·리토스 다운로드는 변경하지 않는다.

## 발견하고 수정한 문제

1. **Mac Office의 대체 그림 누락.** 공개 `2411-Performance_Up.pptx` 5장에서 PDF/PNG의 `blipFill` 전체가 `mc:AlternateContent` 안에 있었다. 직접 자식만 읽어 내장 PNG까지 제외했다. 표시 가능한 대체 그림과 그 가지의 자르기를 읽도록 수정했다.
2. **첨부 개체의 정지 그림 누락.** `alterman_security.pptx`, `bug54570.pptx`, `bug64693.pptx`, `tika-2605.pptx`에서 OLE 프레임 안의 PNG/EMF 미리보기를 제외했다. 안전한 정지 그림만 가져오고 저장한다. 원본 첨부나 외부 주소를 실행하지 않는다. 마스터·레이아웃·그룹에서도 저장 후 그림이 남도록 원본 보존 경로를 보완했다.
3. **도형 안의 그림 채우기 미표시.** `51187.pptx`, `ArtisticEffectSample.pptx`, AASCU·UAEU 공개 자료와 CMU 자료에서 발견했다. 프리셋/자유형 도형의 내부를 그림으로 채우며, 원본 소유 부분의 관계·자르기·불투명도·배치·지원하는 이중톤을 읽는다. 테두리는 별도로 유지한다. 단색/없음으로 바꾸면 그림 채우기를 제거하고 Undo로 복구한다. PPTX 전체를 새로 생성해도 실제 `a:blipFill`로 저장한다.
4. **일부 일본어 자료의 저장 실패.** `with_japanese.pptx`의 `#_ftn1` 내부 책갈피를 ZIP 디렉터리로 해석해 저장에 실패했다. 지원하지 않는 책갈피만 안내하고 나머지 문서는 저장하도록 수정했다.

5. **끝의 줄바꿈 때문에 정상 파일 열기 거부.** Maloney·`bug62513`·HowWeRefactor는 ZIP 끝에 LF 1바이트가 붙어 있었다. CRC가 정상인 자료도 거부해 LF/CRLF 한 번만 허용하도록 보완했다. 긴 ZIP 주석은 그대로 읽고, 임의 바이트·여러 줄 덧붙임·경로 이탈·과대 ZIP은 계속 거부한다. 세 공개 자료 모두 가져오기와 3회 저장을 통과했다.

첫 두 문제는 작은 재현 PPTX 5개에서도 수정 전 그림이 0개인 실패를 확인했다. 수정 후에는 프레임에만 위치가 있는 첨부 그림과 책갈피, 그림 채우기·UI 실행 취소·그림/선의 독립 투명도를 포함한 13개 회귀 검사를 통과했다.

## 공개 파일 대조

- 기존 공개 자료 28개·522장과 고정 Apache POI 커밋에서 추가한 70개를 검사했다. 추가 샘플은 합계 21,384,258바이트이며 [SHA-256 목록](object-presence-samples-2026-11-05.json)에 고정했다.
- 98개 중 **97개·1,043장**은 가져오기·화면의 그림 디코딩·3회 저장/재열기를 완료했다.
- 원본에서 **그림/미디어 미리보기 2,219개, 표 184개**를 개체 단위로 대조했다. 별도로 편집 모델의 **도형 그림 채우기 38개**를 확인했다.
- 대조는 활성 대체 가지, 마스터/레이아웃, 그룹의 원본 부분·도형 ID를 기준으로 한다. 모델의 이미지/미리보기/배경/그림 채우기 해시와 표·텍스트를 매 저장 뒤 비교했다. 슬라이드 번호 같은 동적 필드는 실제 앱처럼 계산한 뒤 비교했다.
- 표 전체 누락, 표시 가능한 내장 그림의 원인 미확인 누락, 그림 디코딩 실패, 저장 후 표·그림 내용 손실은 발견하지 못했다. 이는 검사한 자료 범위의 결과이며 모든 PPTX의 호환성 보증이나 PowerPoint 픽셀 일치 점수가 아니다.

남은 그림 제외 후보 6개는 별도로 확인했다. 외부 링크에만 있고 내장 바이트가 없는 그림 1개(`56812`), 원본에서 숨긴 개체 2개(`bug65228`, `bug65551`), 원본 크기가 0인 그림 2개(`crop-to-0`), `blipFill`에 그림 참조 자체가 없는 개체 1개(`missing-blip-fill`)다. 외부 파일을 임의로 가져오거나 숨김/0 크기를 표시하도록 바꾸지 않았다.

표의 `Header3`가 누락 후보로 잡힌 것은 검사 도구가 글자 사이의 명시적 줄바꿈을 무시했기 때문이다. 원본 줄바꿈을 반영해 재검사했고 표 내용이 있는 것을 확인했다. 글머리표 표시는 원문과 구분해 대조했다.

## 별도 한계

- `Divino_Revelado.pptx` 1개는 ZIP 끝 디렉터리가 없어 Python ZIP 도구에서도 열리지 않았다. 이 자료는 97개 성공 집계에 포함하지 않았다.
- 201,116,481바이트 CMU 강의 1은 실제 HTTP 경로로 단독 가져오기에 성공했다(70장·그림 105개). 일부 영상은 크기/합계 제한으로 정지 미리보기가 되고 200 MiB 원본 보존 한계가 안내된다. 전체 원본 보존·3회 저장 집계에는 포함하지 않는다.
- 처음 192 MiB 파일을 검사 도구의 `route.fulfill`로 전달할 때 브라우저 연결이 닫혔다. 실제 HTTP에서는 가져오기가 성공했다. 큰 파일의 DevTools 전송 부담을 피하도록 QA 도구를 보완했다. 이 실패를 앱 자체의 가져오기 실패로 집계하지 않았다.
- 그림 채우기의 일부 효과/벡터 반복 배치, 패턴 채우기, OLE 원본 편집·실행은 지원 범위 밖이다. 새 원본 PowerPoint 렌더링과의 전 장 픽셀 대조는 이번 검사가 아니다.

## 자동·패키지 검증

- 관련 Playwright 회귀 **108개 통과**, 제외·실패·재시도 0개. 새 회귀 13개는 이 수에 포함된다.
- 새 회귀 13개의 최종 저장 파일 생성 재검사도 모두 통과했다. 이 중 저장/재생성 PPTX **11개**의 스키마·관계·콘텐츠 타입 검사를 원본과 비교해 통과했다.
- ZIP 끝·주석·원본 보존과 IO 방어 관련 33개 검사도 통과했다. 위 108개 검사와 일부 중복되므로 합산하지 않는다.
- TypeScript와 프로덕션 빌드 통과.
- 로컬 Mac 패키지의 별도 임시 프로필에서 실제 파일 IPC의 열기·덮어쓰기·다른 이름으로 저장·취소·외부 변경 보호 등 **12개 흐름 통과**. OS 선택창 응답만 QA가 지정했으며 실제 프린터 출력은 검사하지 않았다.
- 새 Mac 프로덕션 패키지에서 `2411-Performance_Up` 5장, `bug54570` 1장, `51187` 1장을 실제 파일 IPC로 열고 다른 이름으로 저장·재열기했다. 그림/그림 채우기 소스가 동일하며 화면도 확인했다. 이 공개 저장 파일 3개의 구조 검사도 통과했다.
- 패키지의 `dist/`·`electron/` 63개 파일이 현재 빌드와 일치하고 ad-hoc 서명 무결성을 확인했다. ASAR SHA-256: `3ce9e453f658193ddf7826dadbca7a0aa645cf14e679beebe8df4d7af1baf465`. Apple 공증을 뜻하지 않는다.
- Windows/Linux CI 결과는 후속 검증 기록에 추가한다. 그림 수정의 전체 편집기 회귀와 ZIP 후속 수정의 집중 검사를 구분한다.

Mac이 잠겨 있어 사용자가 열어 둔 문서를 확인하거나 설치 앱을 교체하지 않았다. 기존 문서와 복구 자료는 보존했다. 새 앱은 작업 폴더의 `release/Slide Studio.app`에 준비했다.

## 재실행과 증거

```sh
npm run build
npx playwright test tests/picture-presence.spec.ts tests/shape-picture-fill.spec.ts
node scripts/qa-pptx-objects.mjs /path/to/local-inventory.json qa/results/new-object-audit --round-trip
# 저장해 둔 추가 공개 샘플 폴더를 사용할 때:
node scripts/qa-pptx-objects.mjs qa/object-presence-samples-2026-11-05.json qa/results/new-extra-audit --sample-root=/path/to/extra-public --round-trip
```

입력 파일은 읽기 전용이며 검사 전후 SHA-256을 확인한다. 원본·원본 목록·실행 결과·재현 파일·화면·구조 검사 결과는 로컬 `qa/results/object-integrity-20261105/`에 보관한다. `before-roundtrip/`, `extra-before/`, `all-fixed/`, `zip-extra-fixed/`, `table-header-confirm/`, `related-final.json`, `structural-final/`, `schema-validation.json`, `native-production/results.json`으로 구분했다.
