# Slide Studio Android UI 개선 계획

작성일: 2026-11-07 · 기준: 1.6.23 개발 소스, 커밋 `47f55b8`

상태: **설계 제안**. 현재 소스와 공식 문서를 조사한 계획이며, Android 실기기 검증이나 UI 구현을 완료한 결과가 아니다. 이번 산출물은 이 문서이고, APK/AAB 제작·서명·스토어 등록·공개 배포는 별도 작업이다.

후속 진행: 2026-11-07 Android 전용 보기·탐색·발표와 기본 터치 편집을 소스에 반영했다. [구현 내용·검사 결과·패키징 단계에 남은 일](ANDROID-UI-IMPLEMENTATION-2026-11-07.md)을 확인한다. 이 계획 전체가 실기기 검증까지 완료된 것은 아니다.

## 1. 권장 방향

**스마트폰은 안전한 뷰어와 발표 도구를 먼저 만들고, 태블릿은 같은 뷰어 위에 터치 편집 기능을 추가한다.** 현재 데스크톱 리본을 축소해서 넣으면 작은 버튼, 좁은 슬라이드, 잘못된 개체 이동 문제가 반복된다. 화면 크기와 입력 장치에 따라 주변 UI를 바꾸되 문서 모델과 슬라이드 렌더링은 공유한다.

첫 Android 공개 후보의 핵심은 다음 다섯 가지다.

1. 파일 앱·메일·메신저에서 받은 PPTX를 바로 열고, 표·그림을 빠뜨리지 않고 표시한다.
2. 한 손으로 페이지를 넘기고, 두 손가락으로 확대해 작은 글자와 표를 읽는다.
3. 전체 슬라이드 목록·페이지 번호·텍스트 검색으로 원하는 장을 찾는다.
4. 전체 화면으로 발표하고, 큰 버튼과 터치로 이전/다음·포인터·판서를 사용한다.
5. 조회만으로 원본이나 수정 상태를 바꾸지 않고, 원본 파일을 공유할 수 있다.

태블릿의 키보드·마우스·펜 연결과 분할 화면은 다음 단계에 포함한다. 태블릿을 모니터·프로젝터에 연결하는 기능은 UI와 Android 네이티브 연결을 나눠 진행한다. **휴대폰으로 다른 태블릿/PC를 원격 조작하는 기능은 별도 제품 기능**이며, 단순 외부 화면 연결에 포함하지 않는다.

### Android 패키지로 만들 수 있는가?

가능하다. 현재 React/Vite 기반 화면과 문서 처리 코드를 재사용하고 Android WebView 기반 실행 환경을 붙이는 방향이 현실적이다. Capacitor를 우선 검토 후보로 둔다. Electron은 Windows·macOS·Linux용 데스크톱 프레임워크이므로 현재 실행 파일을 그대로 APK로 변환하는 방식은 아니다. [Electron 소개](https://www.electronjs.org/docs/latest/), [Capacitor 소개](https://capacitorjs.com/docs), [Android 실행 환경](https://capacitorjs.com/docs/android)

파일 열기/저장·공유·글꼴 접근·외부 디스플레이·앱 생명주기는 Android 연결 코드가 필요하다. 이 문서는 그 연결에 필요한 UI 계약까지 정하고, 실행 환경 선택과 패키지 제작은 별도로 남긴다. 기존 코드가 Android에서 모두 동일하게 동작한다는 전제는 두지 않는다.

## 2. 현재 UI에서 확인한 수정 대상

아래는 기준 커밋의 정적 코드 확인 결과다. 모바일에서 실제 재현한 오류와 구분한다.

| 현재 구현 | 모바일에서 예상되는 문제 | 계획 |
| --- | --- | --- |
| `src/styles.css`의 `.app-shell`, `src/office-shell.css`의 `.office-shell` 최소 너비 970px | 360~430px 휴대폰에서 화면과 메뉴가 넘침 | 모바일 전용 shell과 창 크기별 배치 도입 |
| 상단 40px + 탭 34px + 리본 97px | 작은 화면에서 슬라이드 높이가 부족함 | 보기에서는 간단한 상·하단 바만 표시 |
| 작은 도구 29px, 좁은 창에서 24~25px까지 축소 | 오터치, 색상·서식 버튼 접근 곤란 | 기본 터치 영역 48×48 논리 단위, 주요 발표 버튼 56 이상 |
| 왼쪽 축소판 238px, 오른쪽 서식 패널 256px | 슬라이드보다 주변 패널이 더 넓어짐 | 휴대폰은 별도 목록/하단 패널, 태블릿은 공간에 따라 한쪽 패널 |
| `App.tsx`의 리본·개체/슬라이드 우클릭 메뉴, HTML `draggable` 축소판 | 우클릭·정밀 드래그에 의존 | 눈에 보이는 더보기 버튼, 터치용 목록 이동과 삽입선 |
| `SlideCanvas.tsx`의 pointer down 선택·드래그·표 셀 선택, 일부 `touch-action: none` | 확대·페이지 넘김이 편집과 충돌할 가능성 | 보기에서는 편집 이벤트를 연결하지 않고 제스처 우선순위 명시 |
| 발표 화면의 배경 클릭은 다음 장, 도구 메뉴는 우클릭 | 도구를 찾기 어렵고 터치 후 원치 않는 페이지 이동 가능 | 터치 발표 바와 명시적 이전/다음, 클릭 합성 방지 |
| `NotesPane.tsx`와 높이 10px의 드래그 경계 | 손가락으로 잡기 어려움 | 노트는 열고 닫는 패널, 태블릿에서 큰 조절 영역 |
| `PresenterView.tsx`의 `window.open` + `BroadcastChannel` | Android의 독립 외부 화면을 자동 지원하지 않음 | 발표 상태/명령은 재사용하고 화면 출력 연결은 추상화 |
| `window.desktop` 파일·최근 파일·PDF·인쇄·업데이트 API | WebView에 이 API가 없어 기능이 비거나 실패할 수 있음 | 기능 가능 여부를 제공하는 플랫폼 어댑터 |
| `index.html`은 device-width viewport, shell은 이미 `100dvh` 사용 | 기본 viewport는 있으나 키보드·시스템 바·노치 대응은 별도 확인 필요 | 실제 가용 영역과 안전 여백을 반영 |

이미 있는 PPTX 파서, 표/그림/벡터 렌더러, GIF·영상·오디오, 검색, 슬라이드 정렬, 판서, 부분 텍스트 서식 기능을 새로 만드는 것으로 계산하지 않는다. 각 기능의 **터치 진입점과 Android 실행 가능성**을 바꾸고 검증한다.

## 3. 모바일 PowerPoint에서 참고할 흐름

Microsoft 공식 Android 안내에는 최근 문서 → 읽기 보기 → 편집 보기의 구분이 있고, 편집 보기에는 선택 대상에 따른 하단 도구가 있다. 이 구조를 참고하되 계정 로그인이나 클라우드 저장을 필수로 만들지는 않는다. [PowerPoint 화면 탐색 안내, Android 부분](https://support.microsoft.com/en-us/accessibility/powerpoint/use-a-screen-reader-to-explore-and-navigate-powerpoint)

일반 터치 가이드는 축소판 선택, 두 손가락 확대/축소, 텍스트 상자 두 번 탭, 개체 선택 후 이동·크기 조절을 안내한다. 태블릿 발표 안내는 좌우 스와이프와 길게 누르는 레이저 포인터를 설명한다. [Android 터치 가이드](https://support.microsoft.com/en-au/powerpoint/powerpoint-for-android-touch-guide), [Android 태블릿 슬라이드 쇼](https://support.microsoft.com/en-au/powerpoint/run-a-slide-show-in-powerpoint-on-your-android-tablet)

이 문서에서 정하는 일반 터치 동작은 **Slide Studio의 설계안**이다. TalkBack용 두 번 탭/두 손가락 제스처를 일반 터치 규칙으로 혼동하지 않는다. PowerPoint 최신 Android 앱을 직접 설치해 관찰한 결과는 아니므로, 구현 시작 때 실제 휴대폰·태블릿의 화면과 함께 확인한다.

## 4. 화면과 입력 방식별 배치

기기 이름이나 Android 여부만으로 화면을 결정하지 않는다. 앱 창의 가용 너비·높이, 입력 방식, 사용자가 선택한 보기/편집 모드를 각각 판단한다. Android의 창 크기 기준을 참고해 다음 배치를 제안한다. [Android 창 크기 분류](https://developer.android.com/develop/adaptive-apps/guides/use-window-size-classes)

| 조건 | 보기/발표 배치 | 편집 배치 |
| --- | --- | --- |
| 좁은 창: 너비 600 미만 | 한 장 + 상단 바 + 하단 탐색, 목록은 별도 화면 | 하단 문맥 도구 + 펼치는 서식 패널 |
| 중간 창: 600 이상 840 미만 | 한 장 중심, 축소판은 선택적으로 표시 | 축소판 또는 서식 중 하나만 열기 |
| 넓은 창: 840 이상 | 축소판 목록 + 슬라이드, 노트 선택 표시 | 간소화된 리본과 한쪽 서식 패널; 실제 공간이 충분할 때만 동시 표시 |
| 높이 480 미만 | 가로 휴대폰으로 취급해 상·하단 바 자동 숨김 | 키보드 입력 중 보조 패널 접고 선택 위치 확보 |
| 넓은 창 + 마우스/키보드 | 터치용 기능을 유지하면서 키보드 탐색 제공 | 데스크톱형 명령 접근 제공, 기기 연결만으로 편집 모드에 진입하지 않음 |

수치는 Android 논리 dp를 참고한 설계 기준이다. 웹 CSS px와 실제 터치 크기는 WebView viewport·밀도 설정에서 검증한다. `devicePixelRatio`로 문서 좌표나 모든 UI 크기를 일괄 곱하지 않는다. `pointer: coarse`뿐 아니라 실제 이벤트의 `pointerType`과 연결된 입력 장치를 함께 고려한다.

태블릿 분할 화면, 폴더블 접기/펼치기, DeX류 창 크기 변경에서도 같은 규칙을 적용한다. 화면 회전만으로 페이지·선택·편집 내용이 초기화되지 않게 한다.

### 스마트폰 보기 화면 초안

```text
┌─────────────────────────────────┐
│ 뒤로   문서 이름…       공유  ⋮  │
│                                 │
│          슬라이드 원본 비율      │
│          표·그림·텍스트          │
│                                 │
│  일부 항목 표시 안내 · 자세히    │  ← 문제가 있을 때만
│                                 │
│ 목록    이전    10 / 48   다음   │
│                      발표       │
└─────────────────────────────────┘
```

실제 배치에서는 발표를 상단 주요 작업으로 옮기거나 하단 항목 수를 줄여 48 이상 터치 영역을 확보한다. 페이지 번호는 눌러 바로 이동한다. 검색·노트·문서 정보는 더보기에서 연다. 1차 뷰어에는 작동하지 않는 편집 버튼을 표시하지 않고, 편집 기능이 준비된 단계에서 명시적인 `편집` 진입점을 추가한다.

### 태블릿 편집 화면 초안

```text
┌─────────────────────────────────────────────────┐
│ 뒤로   문서 이름   저장 상태    실행 취소  발표 ⋮ │
│       선택한 대상에 필요한 큰 도구들             │
├─────────┬─────────────────────────┬─────────────┤
│ 축소판  │                         │ 서식 패널   │
│ 목록    │      슬라이드            │ 선택 표시   │
│         │                         │             │
└─────────┴─────────────────────────┴─────────────┘
```

두 패널은 공간이 충분할 때만 함께 표시한다. 노트는 사용자가 열었을 때만 표시한다. 기존 데스크톱의 첫 제목 슬라이드 시작 방식은 유지하고, **Android의 시작 화면만** `파일 열기 + 최근 문서`를 우선 배치하는 안을 적용한다. 다른 앱의 열기 요청이 있으면 시작 화면을 거치지 않고 해당 파일로 이동한다.

## 5. 우선순위별 개선 항목

### P0-A. 파일 열기와 읽기 전용 상태

- 파일 앱·다운로드·메일·메신저의 `연결 앱으로 열기`와 앱 내부 `파일 열기`를 같은 흐름으로 합친다. 처음 실행 중 들어온 요청도 한 번만 처리한다.
- 대기 화면은 `파일 받는 중 → 문서 읽는 중 → 그림 준비 중`처럼 실제 단계만 표시한다. 실제 진척량을 모르면 거짓 퍼센트를 보여주지 않는다.
- 중복 열기 버튼을 잠그고 취소·오류·앱 복귀 시 해제한다. 취소할 수 없는 처리 구간은 중단 가능 구간과 구분한다. 실패한 요청을 자동으로 무한 재시도하지 않는다.
- 파일을 기본적으로 보기 모드로 연다. 선택·확대·스크롤·노트 읽기·글꼴 측정만으로 dirty/Undo/자동 저장이 생기지 않아야 한다. 단순히 편집 버튼을 숨기는 것으로 끝내지 않고 편집 명령 자체를 모드에 따라 막는다.
- 최근 목록은 문서 식별자와 접근 권한으로 중복을 구분한다. 삭제·권한 만료 시 다시 위치 선택/목록에서 제거를 제공하고, 남아 있는 캐시를 원본인 것처럼 열지 않는다.
- 원본 공유는 재내보내기를 거치지 않고 원본 바이트를 공유한다. 편집본 공유는 저장 완료 후 별도 흐름으로 제공한다.
- 정상 열기 완료 팝업은 띄우지 않는다. 표시 제한은 닫을 수 있는 안내와 상세 보기로 제공하고, 심각한 읽기 실패는 원인과 다음 행동을 표시한다.

Android 파일 선택은 시스템 SAF가 반환하는 URI와 권한을 사용해야 한다. PC의 파일 경로와 동일하게 취급하지 않으며, 읽기 전용 공급자와 쓰기 가능한 공급자를 구분한다. [Android Storage Access Framework](https://developer.android.com/guide/topics/providers/document-provider)

### P0-B. 페이지 탐색·확대·검색

| 상태/동작 | 기대 동작 | 충돌 방지 |
| --- | --- | --- |
| 보기, 화면 맞춤 상태에서 좌우 스와이프 | 한 번의 제스처에 한 장 이동 | 세로 이동 우세·시스템 가장자리 제스처는 가져오지 않음 |
| 보기, 확대 상태에서 한 손가락 끌기 | 현재 슬라이드 안에서 이동 | 경계에 도달해도 바로 다음 장으로 넘어가지 않음; 다음 버튼 사용 |
| 두 손가락 벌리기/모으기 | 손가락 중심을 기준으로 슬라이드 확대/축소 | 두 번째 손가락이 닿으면 개체 이동·페이지 전환 후보 취소 |
| 보기에서 두 번 탭 | 해당 지점 확대 / 화면 맞춤 복귀 | 편집기의 텍스트 두 번 탭과 모드별로 분리 |
| 페이지 번호 탭 | 숫자 입력 후 해당 페이지 이동 | 음수·범위 밖·빈 입력을 안전하게 처리 |
| 목록 열기 | 현재 장이 보이는 축소판 그리드 | 가상화, 현재 장 강조, 숨긴 슬라이드는 숨김 표시 |
| 검색 | 결과 문구·슬라이드 번호 목록과 이동 | 보기에서는 바꾸기 기능을 노출하지 않음 |

전체 문서를 휴대폰 폭에 맞춰 재조판하지 않는다. 원본 종횡비·개체 좌표를 유지하고 슬라이드 전체를 배율로 표시한다. 읽기용 텍스트 추출 보기는 접근성을 위한 보조 기능으로 분리하고 원본 슬라이드와 혼동하지 않게 한다.

제스처 상태를 `대기 / 이동 후보 / 확대 / 페이지 넘김 / 개체 조작 / 판서`로 나눠 한 번에 하나만 실행한다. `pointercancel`, 앱 전환, 화면 회전 시 원상 복구하며, 손을 뗀 뒤 생기는 합성 click으로 추가 이동하지 않는다. 손가락 이동 임계값은 실제 기기에서 조정한다.

### P0-C. 터치 발표와 미디어

- 현재 장에서 `발표`를 눌러 전체 화면에 진입한다. 처음부터 시작은 추가 선택으로 제공한다.
- 화면 한 번 탭은 도구 바 표시/숨김으로 정하고, 페이지 이동은 좌우 스와이프 또는 큰 이전/다음 버튼으로 통일한다. 링크·동영상 재생 버튼의 탭은 페이지 이동으로 이어지지 않는다.
- 발표 바에 이전·다음·현재 페이지·전체 목록·포인터/펜·종료를 제공한다. 세부 색상·굵기는 펼치는 도구 패널로 옮긴다. 터치 가능한 명령이 단축키/우클릭에만 남지 않아야 한다.
- 이동 모드에서 길게 누르면 누르는 동안 레이저를 표시한다. 레이저·펜 모드를 명시적으로 고르는 대체 버튼도 제공한다. 펜을 사용하는 동안 스와이프로 페이지가 바뀌지 않게 한다.
- 판서는 기본적으로 발표 세션에만 보관한다. 문서로 보관을 고른 경우에만 편집 변경으로 만들고, 읽기 전용 파일에는 덮어쓰지 않는다.
- 숨긴 슬라이드 건너뛰기, 슬라이드 링크, 처음/마지막 장, 검은 화면, 종료 후 원래 위치 복귀를 유지한다.
- GIF는 보기/축소판에서 정지 미리보기, 발표의 현재 슬라이드에서 재생한다. 영상·오디오는 재생 버튼을 제공하고 자동 재생이 제한되면 사용자 탭으로 시작한다. 화면을 떠난 미디어는 정지하고, 복귀 시 예기치 않게 소리가 나지 않도록 한다.
- 음량 버튼은 음량 조절을 유지한다. 키보드/리모컨의 방향키·PageUp/PageDown·Space·Esc는 별도 지원한다.
- 시스템 뒤로 가기는 도구 패널 → 발표 종료 순서로 처리한다. 보기/편집에서도 팝업·키보드·현재 모드를 먼저 닫고 문서 이탈을 처리한다. OS의 키보드 뒤로 가기와 중복 처리하지 않는다.

### P0-D. 표·그림 누락 방지와 대용량 보기

모바일의 최우선 품질 조건은 **버튼을 누르기 쉬운 것과 함께, 원래 있던 내용을 잃지 않는 것**이다.

- 기존 `SlideVisual`, 표·차트·그림·벡터 렌더링을 재사용한다. 모바일용 별도 PPTX 해석기를 만들어 호환성을 갈라놓지 않는다.
- 현재 장과 가까운 장을 우선 준비하고, 축소판은 보이는 범위 위주로 그린다. 이 최적화는 렌더링/디코딩에 적용하며 현재 파서가 파일 전체를 읽는 구조를 자동으로 해결한다고 보지 않는다.
- 큰 이미지의 표시용 축소 캐시와 원본을 분리한다. 메모리를 줄이려고 원본 해상도나 표/그림 모델을 삭제하지 않는다. 배경·도형 그림 채우기·OLE 정지 미리보기도 포함한다.
- 실패한 그림은 빈 공간으로 숨기지 않고 그 위치에 `그림을 표시하지 못했습니다`와 재시도/자세히 보기를 제공한다. 원본 포함 여부·지원하지 않는 형식·디코딩 실패를 구분한다. 원본에 없는 데이터를 만들어 정상 표시로 집계하지 않는다.
- 화면 맞춤 크기에서는 축소가 허용되지만, 확대 시 표 글자와 벡터는 선명하게 다시 그린다. 회전이나 화면 크기 변경이 표 행 높이/개체 크기를 문서에 저장하지 않게 한다.
- Android에 없는 글꼴의 대체 상태를 문서 정보에 표시한다. 앱 UI 글꼴과 슬라이드 글꼴을 분리하고, 배포 가능한 글꼴만 포함한다. PC의 설치 Office 글꼴 탐색을 Android에서도 사용할 수 있다고 가정하지 않는다.
- 백그라운드에서 미디어와 불필요한 렌더링을 중지하고, 문서 닫기 시 캐시·object URL·디코더를 해제한다. 읽던 페이지는 위치 정보로 저장하되 원본 삭제/권한 만료 검사를 우회하지 않는다.
- 저메모리 종료 후에는 접근 가능한 문서를 사용자 의도에 맞춰 복원하거나 다시 열기를 안내한다. 편집 복구 데이터는 원본과 구분하고 자동 덮어쓰지 않는다.

기존 데스크톱 개체 검수는 공개 97개·1,043장과 표 184개를 포함한다. 이 결과는 **Android 통과 결과가 아니다**. 기존 manifest·원본 개체 대조·회귀 샘플을 모바일 검수에 재사용한다. 근거: `qa/PPTX-OBJECT-PRESENCE-2026-11-05.md`, `scripts/qa-pptx-objects.mjs`.

### P1-A. 태블릿과 스마트폰의 간단 편집

- `편집`을 눌렀을 때만 개체 선택/이동/키보드를 활성화한다. 편집 종료 후 같은 페이지·확대 위치의 보기로 돌아간다.
- 텍스트는 한 번 탭으로 상자 선택, 두 번 탭 또는 `텍스트 편집` 버튼으로 입력한다. 한글 조합, Android 기본 선택 핸들, 붙여넣기 메뉴를 방해하지 않는다.
- 하단 도구는 선택에 따라 바뀐다. 텍스트: 글자 크기·굵게·기울임·색·정렬. 도형: 채우기·선 색·두께·배치. 그림: 자르기·교체. 공통: 복사·삭제·실행 취소.
- 부분 텍스트 선택은 서식 패널을 열어도 유지한다. 색상은 미리보기와 `적용/취소`를 제공한다. 숫자는 입력 중 보정하지 않고 완료 시 검증한다. `24`, `200`, `-15` 회귀를 포함한다.
- 키보드가 올라오면 선택한 텍스트와 캐럿이 보이도록 뷰포트만 이동한다. 키보드 높이 때문에 원본 슬라이드/텍스트 상자를 늘리거나 재조판하지 않는다.
- 개체 핸들의 표시 크기와 터치 판정 영역을 분리한다. 작은 도형·겹친 도형은 `선택 목록`으로 고를 수 있게 한다. 여러 개체 선택은 명시적 다중 선택 모드를 제공한다.
- 표는 먼저 표 전체를 선택한 뒤 `셀 편집`으로 들어간다. 셀 범위 선택·표 이동·행/열 경계 조절이 한 제스처에 섞이지 않도록 한다. 초기에는 복잡한 표 구조 변경 UI 확대를 후순위로 둔다.
- 슬라이드 목록의 길게 누르기로 복제·복사·붙여넣기·삭제·이동을 제공한다. 재배치는 삽입선을 표시하고, `앞으로/뒤로/번호로 이동`도 제공해 드래그만 강요하지 않는다. 각 작업은 한 번의 Undo로 되돌린다.
- 저장 상태는 `읽기 전용 / 변경됨 / 저장 중 / 저장됨 / 저장 실패`를 구분한다. 원본에 쓸 수 있으면 PPTX 저장, 권한이 없거나 보존 불가 항목이 있으면 이유와 저장 위치 선택을 제공한다. 기본 동작으로 중복 복사본을 만들지 않는다.

### P1-B. 태블릿 연결과 외부 화면

| 연결 방식 | UI 대응 | 구현 경계 |
| --- | --- | --- |
| 태블릿 + 키보드/마우스 | 단축키·포커스·우클릭과 터치 메뉴 공존 | 터치 버튼을 자동으로 작게 만들지 않음 |
| 태블릿 + 펜 | 펜/손가락 동작 구분, 판서 도구, 손바닥 오입력 검사 | 압력·지우개 버튼은 실제 기기 지원을 확인한 뒤 제공 |
| 태블릿/휴대폰 + 화면 미러링 | 슬라이드만 보여주는 안전한 발표 화면, 노트 기본 숨김 | 미러링은 같은 화면이므로 노트를 비공개로 보장할 수 없음 |
| 독립 외부 화면 지원 장치 | 외부: 슬라이드만. 본체: 현재/다음 장·노트·타이머·조작 | Android 디스플레이 감지/출력 어댑터 필요 |
| 다른 태블릿/PC를 원격 조작 | 향후 연결·페어링·권한·연결 끊김 UI | 이번 기본 UI 범위 밖 |

미러링/확장 가능 여부를 확정할 수 없으면 독립 발표자 보기를 활성화하지 않는다. 화면 연결이 끊기면 노트를 외부 출력으로 보내는 대신 출력 종료와 본체 복귀를 처리한다. 본체와 외부 화면에서 음성이 중복 재생되지 않도록 재생 주체도 하나로 정한다.

Android에는 별도 디스플레이에 내용을 보여주는 `Presentation` API가 있지만 모든 연결 장치가 이를 제공하지는 않는다. Cast·USB-C·HDMI를 하나의 자동 지원 기능으로 묶지 않고 실제 장치별로 검증한다. [Android Presentation API](https://developer.android.com/reference/android/app/Presentation)

### P1-C. 접근성·오류 안내

- 메뉴·아이콘의 실제 터치 영역은 최소 48×48 논리 단위로 확보한다. 인접 버튼의 보이지 않는 터치 영역이 겹치지 않게 한다. [Android 터치 영역 지침](https://developer.android.com/guide/topics/ui/accessibility/views/apps-views)
- TalkBack에서 문서 이름·현재 슬라이드/전체 장수·버튼 이름·선택 상태·읽기 순서를 제공한다. 숨겨진 편집 화면이 계속 포커스를 받지 않게 한다.
- 긴 슬라이드 텍스트와 표는 보조 `슬라이드 내용 읽기`로 순서대로 탐색하게 한다. 장식 SVG의 수많은 경로를 읽는 대신 의미 있는 개체/텍스트를 노출한다.
- 글자 크기 확대는 메뉴와 노트에 적용하고, 원본 슬라이드에는 별도 확대 기능으로 대응한다. 시스템 글자 크기 200%에서 메뉴가 잘리지 않는지 검사한다.
- 성공 알림은 짧고 조작을 막지 않게 한다. 파일 실패·미디어 실패는 원인·다음 행동을 보이고, 색상만으로 상태를 구분하지 않는다.

### P2. 첫 버전 이후

고급 표/차트 편집, 마스터 편집, 세밀한 애니메이션 편집, 앱 간 복잡한 클립보드, 클라우드 공동 편집, 원격 발표 제어, Android 인쇄/PDF 출력 확장은 별도 단계로 둔다. 기존 자료를 **표시**하는 기능과 새로 **편집**하는 기능을 혼동하지 않는다. 보호 문서는 관련 기능이 없으면 이유를 안내하고 빈 파일처럼 열지 않는다.

## 6. 코드 작업 분리와 플랫폼 계약

아래 신규 파일명은 제안이며 기존 구현을 확인하며 조정한다.

핵심은 `App.tsx` 전체를 한 번에 재작성하는 것이 아니라, 기존 명령을 추출해 데스크톱 리본과 터치 UI가 같은 함수를 호출하게 하는 것이다. UI 변경을 위해 PPTX 파서와 저장 구조를 동시에 바꾸지 않는다.

플랫폼 계약은 최소 다음 정보를 제공한다.

- 파일 열기 요청/결과: 문서 토큰, 표시 이름, MIME, 바이트 또는 읽기 핸들, 권한, 취소/실패.
- 파일 저장/공유: 원본 쓰기 가능 여부, 저장 위치 선택, 완료/실패, 공유용 임시 파일 수명. Android 공급자에 PC의 원자적 rename이 된다고 가정하지 않는다.
- 환경: 가용 창 크기, 시스템/키보드 여백, 백그라운드/복귀, 뒤로 가기, 화면 유지 요청.
- 기능 가능 여부: 인쇄/PDF, 외부 화면, 글꼴 불러오기, 공유, 업데이트 방식. 미지원 작업은 실제 가능한 대안과 함께 표시한다.
- 발표 출력: 본체/미러링/독립 외부 화면의 상태, 연결 해제, 명령과 슬라이드 동기화. UI가 `window.open` 성공 여부만으로 외부 화면 연결을 판정하지 않게 한다.

APK/AAB 제작을 나중에 하더라도 이 계약은 먼저 설계해야 한다. 다만 모의 어댑터로 통과한 화면을 실제 Android 파일 권한·프로세스 종료·외부 화면 검증 완료로 계산하지 않는다.

## 7. 실행 순서와 예상 공수

1인 개발 기준의 초기 추정이며, Android WebView·실기기 차이 발견 시 재산정한다. **UI 개발·브라우저 검증 공수**로, APK/AAB 제작·서명·배포, 네이티브 파일/공유/외부 화면 플러그인 구현, 별도 Android 통합 검수 일정은 포함하지 않는다.

| 단계 | 작업 | 예상 | 완료 조건 |
| --- | --- | --- | --- |
| A | 모드/명령 경계, 화면 시안, 어댑터 계약, 현재 성능 기준 | 6~10시간 | 보기에서 편집 명령 차단, 3개 폭의 시안과 검수 자료 고정 |
| B | 모바일 시작/보기 화면, 큰 메뉴, 목록·페이지 이동·검색 | 16~24시간 | 360px부터 가로 넘침 없이 파일→보기→찾기 흐름 완료 |
| C | 확대·이동·스와이프, 발표 바·판서·뒤로 가기 | 12~20시간 | 제스처 중복 없음, 메뉴/미디어 탭으로 페이지가 바뀌지 않음 |

| E | 태블릿 간단 편집, 한글 입력, 터치 서식/슬라이드 정렬 | 16~24시간 | 부분 선택·숫자 입력·Undo·저장 왕복 시나리오 통과 |

스마트폰 뷰어 중심 A~D는 **44~70시간**, 태블릿 편집과 공통 마무리까지 **70~110시간**을 초기 범위로 둔다. 기본 접근성과 터치 영역은 B부터 적용하며 F에서 한꺼번에 추가하지 않는다. 외부 화면 분리 UI는 C에서 상태와 시안을 만들고 네이티브 연결 검증은 별도 일정으로 둔다.

가장 먼저 실행할 작업은 A와 B의 최소 보기 화면이다. 360×800 창에서 문서를 열고 한 장을 온전히 본 뒤 이전/다음·목록·확대가 가능한지 확인한다. 이 단계가 통과되기 전에 데스크톱의 모든 메뉴를 모바일로 옮기지 않는다.

### 검증 환경

- 브라우저 자동 검사: 360×800, 412×915, 800×360, 600×960, 800×1280, 1280×800. 599/600/839/840 너비와 키보드 표시로 낮아진 높이도 확인한다.

### 자료와 계측

1. 기존 97개 공개 자료의 원본 개체 대조를 재사용한다. Android에서는 우선 대표 12개를 실기기에서, 전체 corpus는 자동화 가능한 환경에서 돌린 뒤 단말 성능에 맞춰 범위를 확장한다. `실기기 12개`를 `전체 실기기 통과`라고 쓰지 않는다.
2. 대표 자료에는 Mac PNG fallback, OLE 정지 미리보기, 도형 그림 채우기, 0 높이/병합 표, 크롭 그림, 벡터, GIF·영상·오디오, 한글 대체 글꼴을 포함한다.
3. 151장 자료와 약 192MiB 자료는 스트레스 검사로 별도 기록한다. 큰 원본은 가져오기만 성공한 것과 저장까지 성공한 것을 분리한다. 모바일에서 크기 제한이 필요하면 근거와 사용자 안내를 먼저 정한다.
4. 일반 자료의 준비된 다음 장 이동은 p95 200ms 이내를 초기 목표로 한다. 목표 기기·자료를 고정하고 최초 열기, 첫 장 완성, 페이지 이동, UI 응답을 따로 측정한다. 이 수치는 현재 측정 결과가 아니다.
5. 20분 보기/발표와 같은 파일 10회 열고 닫기에서 종료·정지·미디어 누적을 검사한다. 첫 회 캐시 안정화 이후 메모리가 계속 증가하면 캐시/리소스 소유권을 조사한다. `GC 한 번 후 감소`만으로 누수 없음 판정하지 않는다.
6. 원본 XML의 개체/표 내용 대조, 실제 decode 완료, 화면 캡처를 함께 사용한다. 저장 왕복만으로 누락 없음을 판정하지 않는다. Android PowerPoint 비교가 가능하면 동일 파일·동일 글꼴 조건에서 대표 장을 추가 대조한다.

### 공개 후보를 막는 결함

표/그림 전체 누락, 잘못된 파일 열기, 원본 훼손, 조회 중 자동 수정, 반복 열기 충돌, 뒤로 가기 불능, 편집 내용 유실, 필수 버튼 잘림, 노트 외부 노출은 출하 차단 항목이다. 표시 제한을 안내했다는 이유만으로 지원하기로 한 표/그림의 회귀를 통과시키지 않는다.

- 별도 Android 패키징 계획: 실행 환경 확정, 파일 URI/공유/복구, 외부 화면, APK/AAB·서명·배포와 업데이트 경로.
