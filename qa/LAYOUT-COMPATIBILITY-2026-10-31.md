# 웹 PowerPoint 비교와 레이아웃 개선

개발 버전 **1.6.18**은 원본 PPTX의 사진·표·차트·테마 표시와 저장 후 원본 보존을 개선합니다. 시작 소스는 `71249c1`이며, 작업 계획은 2026-10-31 **12:56:18–17:56:18 KST**였습니다. 사용자 요청에 따라 진행 중이던 검증과 추가 요청한 버전 표시 수정을 마무리하고 중지합니다. 공개 릴리스·다운로드 파일·리토스 문서는 갱신하지 않았습니다.

## 비교 범위와 우선순위

공개 파일 20개·93장을 확보했습니다. 그중 그림으로 구성된 31장은 별도로 구분하고, 편집 가능한 원본 개체가 있는 **17개 파일·62장**을 웹 PowerPoint, 기존 Slide Studio, 개선 버전의 같은 브라우저·글꼴 조건으로 대조했습니다. Apache POI의 15개·31장, Dickinson 업무형 9장, DSU 한글 자료 22장입니다. 원본 글꼴이 없는 경우의 줄바꿈 차이를 레이아웃 파서의 오류와 구분합니다.

| 계획 | 우선 작업 |
|---|---|
| 0–30분 | 원본과 비교 기준 고정, 사진 자리표시자 누락 |
| 30–120분 | 표의 테마색·테두리·세로쓰기, 차트 색·숫자·라벨 |

Apache POI 원본은 [고정 커밋의 slideshow 자료](https://github.com/apache/poi/tree/6327f056ba3cfdae326a0261a236460592b80f5c/test-data/slideshow)를 사용합니다. 경로·크기·SHA-256은 [표본 목록](layout-samples-2026-10-31.json)에 기록했습니다. `node scripts/fetch-layout-samples.mjs`와 `node scripts/fetch-workplace-samples.mjs`는 제한된 HTTPS 경로에서 해시가 맞는 공개 파일만 받습니다. 원본 PPTX와 생성 화면은 Git·설치 파일에 넣지 않습니다.

## 저장과 자료 보호

여러 보존 마스터가 같은 테마 부품을 공유한 저장본은 웹 PowerPoint가 복구를 요구했습니다. 다른 요인을 하나씩 고정한 대조본으로 테마 공유를 원인으로 좁혔고, 마스터마다 **내용이 같은 독립 테마**를 연결하도록 수정했습니다. 테마에 연결된 그림·글꼴은 같은 원본을 사용합니다. 세 번 편집·저장한 실제 수정 후보는 웹 PowerPoint의 정상 편집 모드로 열렸습니다. 이 공개 사례의 두 번째·세 번째 저장에서 마스터·레이아웃 수와 압축 해제 크기는 동일해 사본이 계속 누적되지 않았습니다.

최종 확인한 저장본은 **9개**입니다. 업무형 Dickinson, 한글 DSU, 테마·도형·SmartArt·세로쓰기 표·그림 배경 차트와 신규 표·혼합 레이더 시험본이 웹 PowerPoint의 정상 편집 모드로 열렸으며 복구 배너가 없었습니다. 추가 공개 6종은 노트를 바꾸어 세 번 저장했고, 모든 단계의 슬라이드·개체 수, 텍스트·표 내용과 차트 통합 문서가 유지됐습니다. 이는 저장본 열기 검사이며 저장본의 모든 장을 다시 시각 비교했다는 뜻은 아닙니다. 나머지 공개 10종도 로컬 세 번 저장 검사는 통과했으나 사용자 중지 요청에 따라 웹 업로드·열기는 추가하지 않았습니다.

새로 작성한 표의 셀 테두리·채움 XML 순서와 PptxGenJS의 실제 파일이 없는 마스터 형식 선언도 수정했습니다. 저장 결과의 ZIP 디렉터리를 검사해 앱이 다시 열 수 있는 파일·압축 해제·개별 XML 한도를 유지합니다. PptxGenJS의 `notesMasterIdLst` 위치를 바꾸면 웹 PowerPoint가 복구를 요구하는 별도 재현이 있어 생성기의 기존 순서는 유지합니다.

표의 셀을 문서 개체 용량에 포함합니다. 한도를 넘는 복제·붙여넣기·행 추가는 거부하면서 현재 문서, 입력 중인 셀 내용, 수정 상태와 실행 취소 이력을 보존합니다. 한도에 맞는 문서는 저장·재열기를 지원합니다.

읽을 수 없는 자동 저장 원문은 새 작업이 덮기 전에 별도로 보관합니다. 보관에 실패하면 자동 저장을 중지하고 기존 원문과 현재 작업의 수동 PPTX 저장을 유지합니다. 다른 창의 저장과 재시도도 같은 보호를 적용합니다. **보관된 복구 데이터**에서 원문을 내려받아도 보관 자료는 남습니다. 알 수 없는 버전·추가 필드·Blob 바이트는 ZIP에 함께 보존합니다. 256 MiB 다운로드 한도는 큰 Blob을 메모리로 읽기 전에 검사합니다.

## 속도와 메모리

10개 계열·총 10만 점의 합성 차트에서 원본 데이터를 줄이지 않고 SVG 노드를 묶었습니다. 같은 Mac의 측정에서 표시 시간은 약 **9.3초 → 5.7초**, 추가 JS 힙은 약 **223MB → 39MB**였습니다. 작은 차트, 반투명 색과 과도한 스타일 변경은 원래 경로를 사용합니다. 점이 겹치는 경계의 안티앨리어싱은 달라질 수 있으며 픽셀이 동일하다는 뜻은 아닙니다. 전체 앱의 속도 보증이나 프로세스 전체 메모리 측정으로 해석하지 않습니다.

7,200개 셀의 20장 자료에서 160회 rich HTML 붙여넣기, 크기 조절, 12회 취소·다시 실행, 저장과 세 번 재열기의 내용 해시가 일치했습니다. 해당 측정의 재열기 JS 힙은 82.90→83.23→83.32MB, 새 문서 전환 뒤에는 44.48→44.59→43.95MB였습니다. 실제 151장 공개 자료의 127 MiB 초과 복구 저장도 별도 검사합니다.

Mac 패키지에서 151장 자료를 여덟 번 재열어 한글 노트·1,186개 개체·원본 ZIP 해시를 확인했습니다. 미디어 검사 수정 후의 실행은 오류가 없었고 GC 후 JS 힙은 140.78→139.48 MiB였습니다. 프로세스 working set 합계는 1030.05→842.47 MiB, 렌더러 누적 피크는 **1642.67 MiB**였습니다. 앞선 실행의 피크는 1773.83 MiB였으며 무결성 검사 전에 이미 발생했습니다. 실행 간 OS·GC 상태가 달라 이 차이를 개선률로 해석하지 않습니다. 재열기마다 누적되는 JS 누수는 관찰하지 못했어도 큰 문서의 순간 메모리 부담은 남습니다.

별도 프로필의 실제 파일 열기→새 제목 문서 전환 6회에서도 151장·1,186개 개체·원본 해시와 수정 없음 상태가 유지됐습니다. 열린 문서의 GC 후 JS 힙은 57.99→58.32 MiB, 새 제목 문서는 7.43→7.80 MiB였고 지속 증가를 관찰하지 못했습니다. 이 검사와 자동 저장 복구 검사는 측정 조건이 다릅니다. 보조 한글 노트 폐기 후 재열기 단계는 관찰 대기시간 초과로 완료를 확인하지 못했고, 중지 요청 후 재실행하지 않았습니다.

미디어 형식 검사는 전체 base64의 문자·패딩·정확한 바이트 크기를 확인하되 형식 판별에 필요한 앞부분만 디코딩합니다. 같은 151장 자료의 한 번 복구에서 디코딩한 바이트 합계는 **52,719,199 → 7,704**로 줄었고, 전체 반환 모델·이미지 원문·원본 PPTX 해시는 같았습니다. 기존 미디어 회귀 41개와 새 MIME·크기 경계 검사 4개, 실제 앱의 세 번 복구도 통과했습니다. 별도 실행의 최대 메모리는 개선을 입증하지 못했으므로 이 변경은 불필요한 디코딩 제거로 한정합니다. 큰 복구 JSON의 읽기·검증·재생성 비용은 남습니다.

## 검증 상태

레이아웃·저장·미디어 수정 후 전체 실행은 **758개 중 755 통과·3 조건 생략·실패와 불안정 재시도 0개**였습니다. 생략은 비공개 원본 자료, 없는 Office 전용 글꼴, Mac에서 실행할 수 없는 Windows 전용 전체화면 검사입니다. 추가 버전 표시 수정은 관련 **10개 검사**와 타입 검사·production 빌드를 통과했습니다. 버전 표시 검사의 세 플랫폼은 Mac Chrome에서 데스크톱 브리지를 모사하며 실제 각 OS에서 실행했다는 뜻은 아닙니다.

이전 723개 실행은 717 통과·6 생략이었고, 754개 실행은 749 통과·3 생략·2 실패였습니다. 테마 시험 데이터가 고정된 잘못된 파일을 수정하던 두 실패는 실제 소유 관계를 따라가도록 고쳐 관련 7개가 통과했습니다. 초기 Windows CI의 추가 3개 실패도 POSIX 파일 권한·OS 글꼴 합성 폭을 가정한 시험 데이터 문제로 좁혀, 실제 권한 보존과 고정 글꼴의 실제 small-caps 표시를 검증하도록 수정했습니다. 실패 기록을 폐기하거나 조건 생략으로 바꾸지 않았습니다.

레이아웃 수정 Mac 패키지의 production renderer·preload·IPC·파일 쓰기를 사용한 복구 다운로드 **7개 흐름**은 통과했습니다. OS 대화상자의 응답만 검수용으로 공급하며 별도 사용자 프로필과 실행별 임시 폴더를 사용합니다. 원문 바이트, 알 수 없는 버전, 취소·확장자 충돌, 임의 경로 거부, 기존 PPTX 저장 대상과 재열기 후 보관을 확인합니다. `scripts/qa-recovery-download-native.cjs`로 재현하며 기존 큰 문서 검수용 `qa-recovery-native.cjs`와 구분합니다. 보존 ZIP에서 푼 앱으로 실제 저장 12개와 MP3·AAC·WAV·PDF 14개 흐름도 통과했고, 공개 자료 4개·PDF 13쪽의 출력에서 확인한 배경·표·레이더는 유지됐습니다. 실제 프린터 출력은 수행하지 않았습니다.

[Windows·Ubuntu 편집 CI](https://github.com/beaur8-prog/slide-studio/actions/runs/41180631024)는 `d096c11`에서 각 237개 중 Windows 231 통과·6 생략, Linux 229 통과·8 생략으로 실패·불안정 재시도 없이 완료됐습니다. 양쪽 실제 앱의 저장 12개·복구 7개·오디오/PDF 14개도 통과했습니다. 추가 버전 표시 검사 3개는 이 CI 실행 이후 반영했으며 최종 소스의 CI 대상은 240개입니다.

[설치 CI](https://github.com/beaur8-prog/slide-studio/actions/runs/41180632045)는 Windows Setup과 Ubuntu 22.04/24.04에서 모두 성공했습니다. 설치·재설치·제거, 사용자 프로필과 무관한 파일 보존을 확인했습니다. Windows는 기존 기본앱·UserChoice·다른 앱의 등록값/하위 키 12개와 다른 설치의 교체 소유권을 실제로 검사했습니다. 임시 Windows Server 2025와 Linux X11/Xvfb 환경의 결과이며 모든 사용자 환경을 보장하지 않습니다. 보고서·화면만 수집했고 설치 파일은 공개하지 않았습니다.

버전 표시 수정 `3884983`을 포함한 로컬 Mac 앱을 별도로 빌드했습니다. 별도 프로필의 실제 패키지에서 네이티브 버전 `1.6.18`과 상단·파일 메뉴·970px 창의 표시, 도움말 정보 호출을 확인했습니다. 정보 호출은 OS 창을 열지 않도록 검수 중 가로채 호출 여부만 확인했습니다. 사용자의 Mac은 잠겨 있어 실행 중인 앱과 문서를 안전하게 확인할 수 없으므로 기존 앱은 교체하지 않았습니다. 공개 다운로드는 1.6.16으로 유지했습니다.

## 남은 차이

- 원본 Calibri·맑은 고딕 등 글꼴이 없는 기기에는 대체 글꼴의 모양·굵기·줄바꿈 차이가 남습니다. 진단은 글꼴 이름 기준이며 모든 굵기와 문자별 대체를 보장하지 않습니다. [글꼴 범위](../FONT_NOTES.md)를 참고하세요.
- 테마 8·9쪽의 얇은 제목은 원본 `Franklin Gothic Medium`이 없어 `Apple SD Gothic Neo Regular`로 대체된 결과입니다. 원본에는 별도 굵게 속성이 없으며 글꼴명·크기·대문자 속성은 보존됐습니다. 이를 강제로 굵게 바꾸면 원본 의미가 달라집니다.
- 차트 자동 스타일·여백·축 배치 일부는 근사입니다. 음수·로그·역방향 레이더 축과 검증하지 않은 복합 형식은 제한 안내를 표시하고 원본 차트는 보존합니다.
- `mailto` 링크는 원본 외관을 표시하지만 실행하지 않으며 가져오기 안내를 유지합니다.
- 기본 개체 애니메이션 편집·재생 전체, 마스터 편집, 고급 Office 효과의 완전 일치는 이번 범위에 포함하지 않습니다. 이번 자료의 개선을 PowerPoint 전체 호환 점수로 환산하지 않습니다.
