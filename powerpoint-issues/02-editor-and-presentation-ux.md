## 1. 텍스트 및 문단 편집 UX

### 1.1 더블클릭 편집 진입 시 커서 위치 무시 및 리본 클릭 시 편집 모드 강제 해제
- **더블클릭 시 항상 전체 텍스트가 선택됨 (`src/SlideCanvas.tsx:602-610`)**:
  - `EditableText` 진입 시 `useLayoutEffect`가 무조건 `range.selectNodeContents(ref.current)`를 실행하여 텍스트 전체를 블록 지정합니다. PowerPoint처럼 클릭한 글자 위치에 커서를 두거나 더블클릭한 단어만 선택하는 동작이 불가능합니다.
- **리본의 글꼴·글자 크기·정렬·글머리표 클릭 시 편집 종료 (`src/App.tsx:2067-2101, 2814-2855`, `src/SlideCanvas.tsx:628-637`)**:
  - 글꼴 `<select>`(`src/App.tsx:2067-2092`)와 글자 크기 `<NumberInput>`(`src/App.tsx:2093-2101`)에 `data-text-selection-control` 속성이 없고, 문단 정렬 버튼(`src/App.tsx:2814-2830`)에 `preserveTextSelection`이 빠져 있어 클릭하는 즉시 `EditableText`의 `onBlur`가 발생하며 텍스트 편집 모드가 종료됩니다.
  - 홈 리본의 `• 글머리 기호` 버튼(`src/App.tsx:2832-2855`)은 클릭 시 명시적으로 `finish(); setEditing(null);`(`L2840-2841`)을 호출하여 사용자를 텍스트 편집 모드 밖으로 내쫓습니다.

### 1.2 부분 선택 서식(글꼴·크기·정렬) 덮어쓰기 및 서식 손실
- **부분 텍스트의 글꼴(Font Family) 및 글자 크기(Font Size) 변경 불가 (`src/text-formatting.ts:3-25`, `src/text-layout.ts:241-273`)**:
  - `InlineFormat`은 `"bold" | "italic" | "underline"`만, `TextFormat`은 여기에 `"color"`만 지원합니다.
  - 텍스트 일부를 드래그한 뒤 글꼴이나 글자 크기를 바꾸면 `patchText()`(`src/text-layout.ts:266-271`)가 호출되어 **텍스트 상자 안의 모든 문단과 모든 런(Run)의 글꼴/크기를 일괄 덮어써 버립니다**. PPTX에서 가져온 문장 내 부분 크기/글꼴 차이도 한 번 수정하면 모두 사라집니다.
- **개별 문단 정렬 불가 (`src/text-layout.ts:266-271`)**:
  - 제목은 가운데 정렬, 본문은 왼쪽 정렬처럼 한 텍스트 상자 안에서 문단별로 정렬을 다르게 줄 수 없으며, 정렬 버튼 클릭 시 모든 문단의 `align`이 한꺼번에 바뀝니다.
- **리본 색상 표시줄이 현재 커서/선택 영역의 색상을 반영하지 않음 (`src/App.tsx:2155`)**:
  - 글자 색 버튼 아래의 `.color-bar`가 현재 선택된 텍스트 런의 색상이 아닌 `selectedElement?.color || "#233D35"`만 고정 표시합니다.
- **`editText`의 단순 접두/접미 비교로 인한 중간 런 서식 증발 (`src/text-layout.ts:139-239`)**:
  - `editText()`는 이전 문자열과 새 문자열의 공통 접두사(`start`)와 공통 접미사(`end`)만 비교해 그 사이 구간 전체를 단일 `insertedStyle`로 평탄화합니다 (`L188-192`). 맞춤법 자동 교정이나 복수 위치 변경이 일어나면 중간에 있던 런 서식이 모두 초기화됩니다.

### 1.3 글머리표·번호 매기기 및 키보드 편집 동작 불일치
- **특정 문단만 글머리표 토글 불가 (`src/text-bullets.ts:33-69`)**:
  - `toggleTextBullets()`가 커서가 있는 문단이 아니라 텍스트 상자 내 **모든 문단**에 일괄적으로 `"• "`를 붙이거나 제거합니다.
- **번호 매기기 목록(`1.`, `2.`, `a.`) 버튼 및 엔터 자동 증가 부재 (`src/text-bullets.ts:19-20, 114-115`, `src/App.tsx:2832-2855`)**:
  - 리본에 번호 매기기 목록 버튼이 없으며, PPTX에서 가져온 번호 목록에서 `Enter`를 눌러도 다음 번호(`2.`, `3.`)가 이어지지 않습니다.
- **빈 글머리표 줄에서 `Enter` 입력 시 목록이 종료되지 않음 (`src/text-bullets.ts:92-120`)**:
  - PowerPoint에서는 내용 없는 빈 글머리표 항목에서 `Enter`를 누르면 글머리표가 해제되고 일반 문단으로 전환되지만, 현재 `continueTextBullet`은 계속해서 빈 `"• "` 줄을 무한 생성합니다.
- **글머리표 뒤에서 `Backspace` 입력 시 내어쓰기(`indent`)가 남는 버그 (`src/SlideCanvas.tsx:647-666`, `src/text-layout.ts:98-109, 220-223`)**:
  - `"• "` 바로 뒤에서 `Backspace`를 누르면 공백 문자만 지워져 `"•"`가 일반 텍스트로 남으면서 문단의 음수 `indent`(`-hanging`)와 `marginLeft`는 그대로 유지되어 레이아웃이 깨집니다.
- **`Tab` / `Shift+Tab` 다단계 목록 수준 조절 불가 (편집 모드 이탈) (`src/SlideCanvas.tsx:647-666`)**:
  - 텍스트 편집 중 `Tab` 키를 처리하지 않아 브라우저 기본 포커스 이동이 발생하고, `onBlur`가 트리거되어 **텍스트 편집 모드가 곧바로 풀려버립니다**.
- **`Shift+Enter`(줄바꿈)와 `Enter`(문단 바꿈) 구분 소실 (`src/text-layout.ts:198-206`)**:
  - `editText`에서 새로 입력된 모든 `\n`에 무조건 `paragraphBreaks = true`(`L204`)를 부여하므로, `Shift+Enter`를 눌러도 소프트 줄바꿈(`<a:br>`)이 아닌 새 문단이 만들어져 문단 간격(`spaceBefore`/`spaceAfter`)이 중복 적용됩니다.

### 1.4 서식 있는 텍스트 복사·붙여넣기 불가 및 실행 취소(`Ctrl+Z`) 단위 문제
- **텍스트 편집 중 붙여넣기 시 모든 서식 제거 (`src/SlideCanvas.tsx:667-671`, `src/TextContextMenu.tsx:47-60`)**:
  - `onPaste`가 무조건 `text/plain`만 읽어 삽입하므로, 같은 텍스트 상자 안에서 굵고 빨간 글씨를 복사해 붙여넣어도 일반 평문으로 붙여넣어집니다.
- **텍스트 편집 세션 전체가 단 1개의 Undo 단계로 묶임 (`src/SlideCanvas.tsx:1154, 1164-1167`, `src/App.tsx:559-604`)**:
  - 텍스트 상자 편집을 시작할 때 `begin()`을 한 번 호출하고 포커스를 잃을 때 `finish()`를 호출합니다. 편집을 마친 뒤 `Ctrl+Z`를 누르면 방금 입력한 여러 문장이 단어/문장 단위가 아니라 **편집 세션 시작 전 상태로 한꺼번에 전부 되돌아갑니다**.

## 2. 캔버스 및 개체 조작 UX

### 2.1 내부 복사 후 외부 클립보드 붙여넣기 차단 버그 및 텍스트 붙여넣기 미지원
- **외부 이미지 붙여넣기 차단 버그 (`src/App.tsx:1030-1042, 1789-1798, 1883-1904`)**:
  - 앱 내에서 도형이나 슬라이드를 한 번이라도 복사(`Ctrl+C`)하면 메모리 내 `clipboard.current.elements` 또는 `clipboard.current.slide`가 영구히 남습니다.
  - 이후 외부 앱(브라우저, 캡처 도구 등)에서 이미지를 복사한 뒤 Slide Studio에서 `Ctrl+V`를 누르면, `keydown` 핸들러(`src/App.tsx:1790-1797`)가 `clipboard.current`가 있다는 이유로 `e.preventDefault()`를 호출하고 이전에 복사했던 내부 도형/슬라이드를 붙여넣어 버립니다. 이로 인해 브라우저의 `paste` 이벤트(`src/App.tsx:1883-1904`)가 발생하지 않아 **외부 이미지를 `Ctrl+V`로 붙여넣을 수 없게 됩니다**.
- **캔버스에 외부 텍스트 `Ctrl+V` 붙여넣기 무시 (`src/App.tsx:1883-1904`)**:
  - 텍스트 상자 편집 중이 아닐 때 외부에서 복사한 텍스트를 슬라이드 위에서 `Ctrl+V`로 붙여넣으면 아무 동작도 하지 않습니다(PowerPoint는 새 텍스트 상자를 생성하여 붙여넣음).

### 2.2 빈 공간 드래그 선택(Marquee Selection) 및 그룹화(`Ctrl+G`) 부재
- **마우스 드래그 범위 선택 불가 (`src/SlideCanvas.tsx:1070-1082`, `src/App.tsx:3413-3415`)**:
  - 슬라이드 빈 영역에서 마우스를 드래그해 여러 개체를 한 번에 선택하는 고무줄 선택 상자(Marquee/Lasso) 기능이 없으며, 다중 선택은 오직 `Shift+클릭`(`Ctrl/⌘+클릭`도 미지원, `src/SlideCanvas.tsx:963`)으로만 가능합니다.
- **개체 그룹화/그룹 해제(`Ctrl+G` / `Ctrl+Shift+G`) 불가 (`src/types.ts:95-143`, `src/insert-content.ts:278-645`)**:
  - 그룹 기능이 전혀 없으며, 특히 **삽입 → 차트 / 다이어그램 / 분수 수식**으로 만든 개체들은 생성 직후 수십 개의 조각(막대, 눈금선, 레이블, 사각형)으로 흩어져 있어 위치를 옮기거나 크기를 바꾸려면 모든 조각을 일일이 `Shift+클릭`해야 합니다.

### 2.3 다중 선택 리사이즈 왜곡, 회전 핸들 부재, 회전 개체 리사이즈 버그
- **다중 선택 리사이즈 시 상대 위치 미비례 (`src/SlideCanvas.tsx:1001-1046`)**:
  - 여러 개체를 선택한 뒤 크기 조절 핸들을 끌면 전체 선택 영역이 비율대로 커지는 것이 아니라, 각 개체의 제자리에서 동일한 `dx`, `dy` 픽셀만큼만 개별 크기가 변합니다.
- **`Shift` 비율 고정 리사이즈 결함 및 이미지 기본 비율 미고정 (`src/SlideCanvas.tsx:1031-1034`)**:
  - 모서리 핸들에서 `Shift`를 누르고 세로 방향(`dy`)으로만 끌면 `dx ≈ 0`이어서 크기가 전혀 변하지 않으며(`height = (width * e.height) / e.width`), 이미지도 `Shift`를 누르지 않으면 모서리 드래그 시 가로세로 비율이 깨집니다.
- **캔버스 회전 핸들 부재 및 회전된 개체 리사이즈 좌표계 오류 (`src/SlideCanvas.tsx:993-994, 1019-1035, 1259-1268`)**:
  - 선택된 개체 위에 마우스로 돌릴 수 있는 회전 핸들이 없습니다(기본 접혀 있는 우측 서식 패널에서 숫자로만 입력 가능).
  - 회전된 개체(`e.rotation !== 0`)의 리사이즈 핸들을 끌 때 화면 좌표계의 `dx`/`dy`를 개체의 로컬 회전 좌표계로 변환하지 않아 크기와 위치가 엉뚱한 방향으로 찌그러집니다.
- **직선/화살표의 끝점(Endpoint) 드래그 불가 (`src/SlideCanvas.tsx:431-455, 1259-1268`)**:
  - 직선과 화살표가 양 끝점 2개가 아니라 일반 사각형과 동일한 8개 바운딩 박스 핸들을 사용하여, 마우스로 끝점을 끌어 각도와 길이를 직관적으로 조절할 수 없습니다.

### 2.4 스마트 가이드(안내선) 다중 드래그 붕괴 버그 및 정렬 도구 한계
- **다중 선택 드래그 시 안내선 스냅이 개체들을 한 점으로 모으는 버그 (`src/SlideCanvas.tsx:1011-1016`)**:
  - 안내선(`showGuides`)이 켜져 있을 때 여러 개체를 함께 드래그하면, 각 개체의 중심이 개별적으로 슬라이드 정중앙에 스냅되어 선택된 개체들이 슬라이드 중앙 한곳으로 겹쳐집니다.
- **개체 간 스마트 가이드 및 상/중/하 정렬·가로/세로 간격 동일 분배 부재 (`src/App.tsx:1166-1182, 3802-3836`)**:
  - 다른 개체의 모서리나 중심선에 맞춰주는 동적 스마트 가이드가 없고 오직 슬라이드 중앙선에만 스냅됩니다.
  - 정렬 기능은 슬라이드 기준 좌/중/우(`left`/`center`/`right`) 3가지만 존재하며, 선택된 개체들끼리의 정렬이나 위/가운데/아래(`top`/`middle`/`bottom`) 정렬, 가로/세로 간격 균등 배분(Distribute)이 없습니다.

### 2.5 방향키 미세 이동(Nudging) 시 Undo 히스토리 오염
- **위치**: `src/App.tsx:163, 1816-1844`
- **현상**: 방향키를 길게 눌러 개체를 이동할 때 매 `keydown` 이벤트마다 `commit()`이 호출되어 60단계(`LIMIT = 60`)인 실행 취소 히스토리가 몇 초 만에 방향키 1px 이동 기록으로 가득 차 이전 작업 취소가 불가능해집니다.

## 3. 표(Table) 편집 UX

### 3.1 캔버스 직접 인라인 입력 불가 (별도 모달 강제) 및 `Esc` 시 변경 유실
- **위치**: `src/SlideCanvas.tsx:894-958, 1142-1151`, `src/TableEditor.tsx:133-829`
- **현상**:
  - 슬라이드 위의 표 셀을 클릭하고 키보드로 글자를 입력해도 아무 반응이 없으며, 반드시 더블클릭이나 `Enter`로 별도의 모달 대화상자(`TableEditor`)를 열어야만 텍스트를 고칠 수 있습니다.
  - 모달 안에서는 실제 슬라이드의 열 너비 비율과 무관한 균등 폭 `<textarea>` 그리드(`repeat(columns, minmax(120px, 1fr))`)로 표시되어 줄바꿈 위치를 가늠할 수 없으며, 실수로 `Esc`를 누르거나 모달 바깥 배경을 클릭하면 입력 중이던 모든 내용이 확인 없이 날아갑니다 (`src/TableEditor.tsx:426-428, 452-455`).

### 3.2 `Tab` 셀 이동, 엑셀/TSV 다중 셀 붙여넣기, 셀 병합/분할, 행 자동 높이 미지원
- **캔버스 및 모달 내 `Tab` 동작 불일치 (`src/App.tsx:1734-1761`, `src/TableEditor.tsx:456-473, 613-633`)**:
  - 캔버스에서 표 셀 선택 중 `Tab`을 누르면 다음 셀로 이동하지 않고 포커스가 다른 개체로 빠집니다.
  - `TableEditor` 모달의 마지막 셀에서 `Tab`을 누르면 PowerPoint처럼 새 행이 추가되지 않고 하단 드롭다운 컨트롤로 포커스가 이동합니다.
  - 엑셀이나 구글 시트에서 복사한 다중 행/열(탭·줄바꿈 구분) 텍스트를 `TableEditor`의 셀이나 캔버스의 선택된 표 셀에 `Ctrl+V`로 붙여넣어도 여러 셀로 나뉘어 들어가지 않고 단일 `<textarea>` 안에 탭 문자열 그대로 들어갑니다 (`src/TableEditor.tsx:620-633`, `src/App.tsx:1889-1893`).
- **셀 병합(`Merge`)·분할(`Split`) 및 위쪽 행/왼쪽 열 추가 불가 (`src/TableEditor.tsx:396-415, 512-531`)**:
  - 셀 병합과 분할 UI가 없으며, 행/열 추가는 항상 현재 선택 셀의 **아래쪽/오른쪽**으로만 삽입되어 첫 번째 행 위나 첫 번째 열 왼쪽에 새 행/열을 추가할 수 없습니다.
  - 표나 셀이 선택된 상태에서는 홈 리본의 글꼴·크기·굵게·정렬 도구가 전부 비활성화(`disabled={selectedElement?.type !== "text"}`)되며, `TableEditor` 안에도 셀 굵게(`bold`)/기울임(`italic`)/밑줄(`underline`) 토글 버튼이 없습니다 (`src/App.tsx:2070-2142, 2827`, `src/TableEditor.tsx:640-805`).
- **행 높이 고정으로 인한 셀 텍스트 잘림 및 경계선 리사이즈 방식 차이 (`src/TableEditor.tsx:81, 117`, `src/table.ts:315-373`)**:
  - 셀 내용이 길어져 여러 줄이 되어도 행 높이가 자동으로 늘어나지 않고 `overflow: hidden`에 의해 슬라이드에서 글자가 잘립니다.
  - 행/열 경계선을 드래그할 때 표 전체 크기는 고정된 채 아랫줄/오른쪽 열의 크기를 깎아먹는 방식으로만 동작합니다 (`src/table.ts:359-360`).

## 4. 슬라이드 관리 및 발표 모드(Slide Show) UX

### 4.1 빈 캔버스에서 `Delete` 키로 슬라이드가 통째로 삭제되는 위험한 동작
- **위치**: `src/App.tsx:929-943, 1801-1804`
- **현상**:
  - `removeSelected()` 함수(`src/App.tsx:929-943`)가 `if (selected.length) { ... } else removeSlide();`로 구현되어 있습니다.
  - 사용자가 슬라이드 캔버스에서 개체 선택을 해제한 뒤 무심코 `Delete`나 `Backspace`를 누르면 **현재 슬라이드 한 장 전체가 즉시 삭제**됩니다. PowerPoint에서는 왼쪽 슬라이드 썸네일 목록에 명시적으로 포커스가 있을 때만 슬라이드가 삭제됩니다.

### 4.2 슬라이드 다중 선택, 썸네일 우클릭 메뉴, 기존 슬라이드 레이아웃 변경, 슬라이드 정렬 뷰 조작 부재
- **슬라이드 다중 선택 및 우클릭 컨텍스트 메뉴 없음 (`src/App.tsx:356, 3297-3406`)**:
  - `activeId`가 단일 문자열로만 관리되어 `Shift+클릭`이나 `Ctrl/⌘+클릭`으로 여러 슬라이드를 한꺼번에 선택·이동·복제·삭제·숨김 처리할 수 없으며, 썸네일 우클릭 메뉴도 없습니다.
- **기존 슬라이드의 레이아웃 변경 불가 (`src/App.tsx:2228-2246, 2780-2790, 3935-3955`)**:
  - 리본과 우측 서식 패널의 모든 레이아웃 버튼이 현재 슬라이드의 레이아웃을 바꾸는 대신 `addSlide(id)`를 호출해 새 슬라이드를 추가합니다.
- **슬라이드 정렬(Slide Sorter) 뷰에서 드래그 순서 변경 불가 (`src/App.tsx:3370-3406`)**:
  - 슬라이드 정렬 화면(`.slide-sorter`)의 카드들에는 `draggable` 속성과 드래그 이벤트 핸들러가 아예 없으며, 카드를 클릭하면 곧바로 정렬 뷰가 닫혀버려(`setSorter(false)`) 정렬 뷰에서 슬라이드 순서를 바꾸거나 삭제/복제할 수 없습니다.
- **왼쪽 썸네일 아래쪽 드래그 시 삽입 위치 오차 (`src/App.tsx:3300`, `src/model.ts:316-320`)**:
  - 위쪽 슬라이드를 아래쪽 슬라이드(`i`) 위로 끌면 `i`번 슬라이드 상단에 `drop-before` 파란 선이 표시되지만, `reorder()`가 앞쪽 요소를 먼저 제거한 뒤 인덱스 `i`에 삽입하므로 실제로는 `i`번 슬라이드 **아래**에 들어갑니다.

### 4.3 발표 모드: 죽은 코드(`presentNotes`), 판서(Ink) 증발, 단축키 누락
- **작동하지 않는 발표자 노트 오버레이(`presentNotes`) (`src/App.tsx:503, 4444-4452`)**:
  - `const [presentNotes, setPresentNotes] = useState(false)`와 `.present-notes` 렌더링 코드가 존재하지만, 코드 전체에서 `setPresentNotes`를 호출하는 버튼이나 단축키가 단 한 곳도 없어 발표 중 노트를 볼 수 없으며 듀얼 모니터 발표자 보기(Presenter View)도 없습니다.
- **발표 종료 시 펜 판서(Ink) 보관 확인 없이 즉시 삭제 (`src/PresentationInk.tsx:60-61, 84`)**:
  - PowerPoint는 펜으로 판서한 뒤 발표를 끝낼 때 판서 내용을 슬라이드에 유지할지 묻지만, Slide Studio는 발표 종료 즉시 모든 판서를 폐기합니다. 형광펜(Highlighter) 도구도 없습니다.
- **발표 모드 단축키 차이 (`src/App.tsx:1616-1677`, `src/PresentationInk.tsx:194-236`)**:
  - `W` 또는 `,` (흰 화면 전환), `.` (검은 화면 전환), `N` (다음 장), `P` (이전 장) 단축키가 없습니다.
  - 숫자 입력 버퍼가 비어 있을 때 `Backspace`를 눌러도 PowerPoint처럼 이전 슬라이드로 이동하지 않습니다 (`src/App.tsx:1657-1659`).
