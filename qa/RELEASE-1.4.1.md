# Slide Studio 1.4.1 배포 검증

2026-10-18(KST), macOS arm64에서 검사했다. GitHub `main`의 PC 작업 `b51088b`·`268ca2e`·`16c80d8`을 가져와 Mac ARM64와 Windows x64 배포 ZIP을 만들었다. 사용법은 [README](../README.md), 배포 파일은 [1.4.1 릴리스](https://github.com/beaur8-prog/slide-studio/releases/tag/v1.4.1)에 있다.

## 포함된 변경

- 발표 중 숨긴 장 건너뛰기, 숫자+Enter 직접 이동, 검은 화면 해제 후 같은 장 표시와 종료 화면.
- 발표 중 편집 명령·입력 격리와 마우스 휠 탐색.
- PPTX 기본 글자 크기 상속, 그룹의 뒤집기·회전, 글머리표 자체 서식, 번호 들여쓰기와 문단 간격 보정.
- 텍스트 편집에서 빈 문단·문단 안 줄바꿈·번호 서식 보존.
- 저장 문서 목록을 닫으면 문서·이미지 참조를 해제하고 늦게 완료된 읽기를 무시하도록 수정.

이번 Mac 배포 준비에서 앱 동작 코드를 추가로 변경하지 않았다. 버전·문서와 Mac에서 올바른 커서 이동을 사용하는 테스트 코드를 갱신했다.

## 자동 검사와 메모리

`npm run build`를 통과했고 전체 `npm test` 결과는 **88개 통과, 2개 제외, 실패·불안정 재시도 0개**, 136.3초다. 제외된 검사는 Windows 실제 창의 전체 화면 경계와 기존 Office 캐시 글꼴을 요구한다.

처음에는 문단 편집 검사 2개가 실패했다. macOS의 Cmd+Home/End는 화면을 스크롤하지만 선택 영역을 해제하지 않아, 뒤에 입력한 글자가 기존 텍스트를 대체하는 테스트 입력 문제였다. 독립 브라우저에서 선택 범위를 측정한 뒤 Mac은 Cmd+Up/Down, 다른 환경은 Ctrl+Home/End를 사용하도록 테스트만 수정했다. 해당 6개 검사와 전체 검사를 다시 통과했다.

문서 목록 검사는 14,442,976바이트(약 13.77 MiB)의 이미지 문자열을 포함한 문서를 연다. 닫기 버튼·Esc·바깥 영역·문서 선택·새 문서의 5개 경로에서 닫은 뒤 JavaScript 힙은 기준 10,563,660바이트와 비교해 최대 496,872바이트(약 0.47 MiB) 차이였다. 읽기가 닫힌 뒤 늦게 완료되는 경우도 기준 10,562,952바이트에서 10,574,452바이트로 돌아왔다. 강제 GC를 포함한 회귀 계측이며 운영체제 전체 메모리나 모든 누수를 검증한 결과는 아니다. 앞선 PC 계측은 [메모리 검증 기록](MEMORY-2026-10-17.md)에 있다.

300장 합성 문서는 재열기 1.502초, 자동 키 입력 10회 0.333초, 편집 종료 후 저장 표시까지 0.258초였다. 한 번의 macOS Chrome 측정이며 다른 기기의 속도를 보장하지 않는다.

## 실제 Mac 배포 앱

배포 ZIP을 임시 폴더에 풀어 서명을 검사하고 `/Applications/Slide Studio.app`에 설치했다. 이전 앱과 사용자 프로필을 백업했으며 설치된 1.4.1의 ASAR 해시는 두 ZIP과 같다.

- 기존 사용자 문서가 정상적으로 열렸다. 별도 4장·21개 개체의 검증 프로젝트로 검사한 뒤 원래 5장짜리 사용자 문서로 돌아왔다.
- 한글·영문·숫자 붙여넣기, Shift+Enter와 빈 줄을 포함한 여러 줄 붙여넣기를 확인했다. 저장된 텍스트는 `한글 ABC 123\n둘째 줄\n\n넷째 줄`과 정확히 같다. 실제 OS IME 조합 입력 검사는 아니다.
- 발표가 네이티브 전체 화면으로 전환됐다. 방향키는 숨긴 2번을 건너뛰어 3번으로 이동했고 숫자 2+Enter는 숨긴 장으로 직접 이동했다.
- 영문 입력 상태의 B로 화면을 가리고, 방향키를 한 번 누르면 동일한 2번 장이 다시 표시됐다. 한글 입력 상태의 B는 동작하지 않아 영문 전환이 필요했다.
- 발표 중 Cmd+O는 파일 창을 열지 않았다. End와 다음 장 입력으로 종료 안내를 보고 Esc로 시작 장인 1번 편집 화면에 돌아왔다.
- 네이티브 저장 창으로 `.slide`를 저장했다. 의도한 텍스트 수정 외에는 입력 JSON과 동일하며 숨긴 장 설정도 유지했다.
- PPTX를 내보내고 다시 열어 4장·빈 줄·한글·노트·2번 장 숨김을 확인했다. PPTX 내부의 빈 문단과 `show="0"`도 검사했다.
- PDF는 960 × 540포인트의 4페이지다. 숨긴 장을 포함한 전체 문서를 출력하며 모든 페이지를 렌더링해 배경·한글·빈 줄·배치를 확인했다. 노트와 편집 도구는 제외됐다.

## 패키지와 다운로드 주소

두 ZIP 전체 CRC32 검사를 통과했다. 공통 ASAR SHA-256은 `3d5284856a768b2b00b72ced69b9862b759399fa52de793b1f03bbc95170b679`다. 1.4.1 배포 매니페스트를 검사하고 ASAR의 프로덕션 자산·Electron 셸 23개 파일을 작업 사본과 바이트 단위로 비교했다. Carlito·나눔바른고딕과 해당 라이선스를 포함하며 Office 캐시 글꼴은 배포하지 않는다.

Mac ZIP에서 추출한 앱과 설치 앱은 `codesign --verify --deep --strict`를 통과했다. Windows 패키지는 공식 Electron 42.11.15 런타임의 SHA-256, PE x64 구조, 제품 메타데이터, 필수 파일과 원본 코드 섹션 보존을 확인했다.

| 파일 | 바이트 수 | SHA-256 |
| --- | ---: | --- |
| Slide-Studio-mac-arm64.zip | 128864279 | `724df747402fa328591b764e55bc9e1093a32b560634b288474073c0d76aeaa1` |
| Slide-Studio-win-x64.zip | 156037189 | `b0887354bc29944d5fa41811ed5e4dca29f64e960f464efdedf9c8f8d18a5130` |

기존 리토스 공유 문서는 `releases/latest/download/` 주소로 앱과 검증값을 연결한다. 새 버전을 GitHub 최신 공개 릴리스로 게시하면 같은 버튼이 새 파일을 받는다. 파일 교체를 위해 공유 문서·토큰·서버·터널을 새로 만들거나 재시작하지 않는다. 문서 본문에 명시된 1.4.0 사용 안내 및 당시 검증 기록은 그대로 두며 최신 변경·검증 기록은 GitHub 릴리스와 이 문서에서 제공한다.

## 한계와 증거 파일

이전 PC 작업의 실제 실행 기록은 있지만 이번에 재생성한 Windows 1.4.1 ZIP을 이 Mac 세션에서 Windows로 실행하지는 않았다. 실제 OS IME와 종이 출력도 미검증이다. Mac은 ad-hoc 서명이며 공증하지 않았고 Windows는 배포 서명이 없다. 없는 원본 글꼴, 복잡한 효과·벡터 형식과 지원하지 않는 PowerPoint 기능에는 차이가 남는다.

로컬 결과는 `qa/results/release-1.4.1/`의 `tests.json`, `native-verification.json`, `asar-verification.json`, `package-verification.json`, `library-heap.json`, `late-library-heap.json`, `corpus-summary.json`과 `qa/results/release-1.4.1-corpus/corpus.json`에 있다. ZIP 검증은 `release/VERIFICATION.json`, Windows 런타임 검증은 `release/BUILD-win-x64.json`에 있다. 생성 결과·공유 설정·원본 샘플은 Git에 포함하지 않는다.
