# Android 슬라이드 쇼 전체 화면 개선 — 2026-11-08

## 바뀐 동작

Android 슬라이드 쇼는 원본 비율을 유지하면서 화면 전체의 가용 너비와 높이를 사용한다. 하단 발표 바에 예약하던 80px과 시스템 안전 여백을 슬라이드 영역에서 제거했다. 도구를 열어도 슬라이드를 축소하거나 옮기지 않고 위에 겹쳐 표시한다.

- 발표 시작과 장 전환 때는 도구 바를 숨긴다.
- 좌우 스와이프로 이전/다음 장을 표시하며, 발표의 숨김 슬라이드는 건너뛴다.
- 발표 중 이전/다음 버튼과 페이지 번호 입력 팝업을 제거했다. 보기 모드의 페이지 탐색은 유지한다.
- 화면 탭으로 포인터·판서·검은 화면·종료 도구를 열고 닫는다. 도구는 약 4초 후 숨긴다. 키보드/스크린리더 포커스가 도구 안에 있으면 숨기지 않는다.
- 길게 누르는 동안 레이저를 표시한다. Android 길게 누르기의 브라우저 문맥 메뉴가 별도 발표 팝업을 열지 않게 했다.
- 마지막 장 이후에는 종료 도구를 표시하며, Android 뒤로 가기와 Esc로도 발표를 끝낼 수 있다.
- 데스크톱의 클릭 진행·숫자 이동·리본·발표 도구 동작은 유지한다.

화면과 슬라이드 비율이 같으면 화면 전체를 채운다. 16:9 슬라이드를 20:9 휴대폰에 표시하는 경우처럼 비율이 다르면, 일부 내용을 자르거나 글자·그림을 늘리지 않고 최대 크기로 맞춘다. 남는 공간은 검은 여백이다.

## 상태바·탐색바와 회전 연결

Android 브라우저의 전체 화면 요청에 `navigationUI: "hide"`를 전달한다. 이 옵션은 브라우저 UI를 숨기도록 요청하는 방식이며, 최종 허용 여부는 브라우저가 결정한다. [Fullscreen API 설명](https://developer.mozilla.org/en-US/docs/Web/API/Element/requestFullscreen)

Capacitor Android 호스트에서는 사용 가능한 `SystemBars` 플러그인을 찾아 발표 진입 때 `hide()`, 종료 때 `show()`를 호출한다. 이 API는 상단 상태바와 하단 탐색바를 대상으로 하며 Capacitor 8의 core에 포함돼 있다. 늦게 끝난 숨김 요청이 종료 뒤 편집 화면의 바를 다시 숨기지 않도록 요청을 순서대로 처리한다. [Capacitor SystemBars API](https://capacitorjs.com/docs/apis/system-bars)

가로 슬라이드는 가로 방향, 세로 슬라이드는 세로 방향 잠금을 요청한다. 네이티브 `ScreenOrientation` 플러그인이 있으면 사용하고, 없으면 전체 화면 진입 후 브라우저 화면 방향 API를 사용한다. 지원하지 않는 환경에서는 방향 잠금 실패로 발표를 중단하지 않는다. 발표 종료 때 이 세션에서 얻은 방향 잠금을 해제한다.

Android의 시스템 가장자리 제스처는 가로채지 않는다. 시스템 바가 필요한 경우 잠시 드러날 수 있다. Android 자체의 몰입 모드 동작과 앱 창/DeX의 캡션 바 정책은 OS가 관리한다. [Android 몰입 모드 지침](https://developer.android.com/develop/ui/views/layout/immersive)

이번 작업은 UI 소스와 네이티브 API 연결을 반영한 것이다. Android 프로젝트/APK를 새로 만들지 않았으며, **실제 Android 상태바·탐색바 숨김과 물리 화면 회전은 APK 실기기 검증이 남아 있다.** 브라우저 모사 및 네이티브 API 모의 연결 결과를 실기기 결과로 계산하지 않는다.

## 검증

- 총 47개 중 **46개 통과, 1개 건너뜀**, 실패 없음.
- 건너뛴 항목은 이 Mac에서 실행할 수 없는 실제 Windows 네이티브 창 전체 화면 검사다.
- Android UI·플랫폼 격리 19개, 몰입 모드 연결 5개와 기존 데스크톱 전체 화면·발표 이동·판서 검사를 실행했다.
- 800×360, 1280×800, 412×915, 1280×720 화면에서 표시 크기가 `min(화면 너비/슬라이드 너비, 화면 높이/슬라이드 높이)`에 일치했다.
- 1280×720의 16:9 화면에서는 16:9 슬라이드가 여백과 발표 바 없이 전체 화면을 채웠다. 화면 캡처도 확인했다.
- 스와이프 후 추가 넘김이 없고 도구 바가 나타나지 않는지, 필요할 때만 도구가 나타나는지, 도구를 열어도 표시 크기가 유지되는지 확인했다.
- Android 브라우저의 실제 Fullscreen 진입을 확인했다. 모의 네이티브 연결에서 바 숨김/복원, 가로/세로 방향 요청과 해제, 지연된 숨김과 종료의 순서, API 실패 후 정상 발표를 확인했다.
- TypeScript와 프로덕션 빌드 통과. 새 npm 의존성 없음.
