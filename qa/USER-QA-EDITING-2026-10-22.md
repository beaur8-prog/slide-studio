# 편집·실행 취소·용량 제한 검수 결과

최종 소스 검사: `tests/user-editing-history.spec.ts` 8/8, `tests/document-capacity.spec.ts` 2/2 통과. 관련 기존 검사: 부분 글꼴 서식 및 개체 우클릭 13/13, 그룹·회전·정렬과 숫자 입력 16/16 통과. 중복을 제외한 이 영역의 검사 39개 통과. Mac Chrome의 독립 프로필에서 사전 구성 문서를 연 뒤 마우스·키보드·실제 편집 이벤트로 검증했다. 실제 Windows 실행을 뜻하지 않는다.

## 확인하고 고친 문제 5종

1. **첫 텍스트·노트 편집 중 상단 실행 취소가 비활성화됨.** 텍스트를 편집하고 포커스를 유지하면 완료된 문서 이력만 검사하므로 Undo가 비활성화되었다. 키보드로 텍스트 실행 취소 후 상단 Redo도 같은 문제가 있었다. 텍스트는 브라우저의 편집 이력에 연결하고 클릭할 때 선택·포커스를 유지한다. 노트의 진행 중 편집도 Undo 버튼에 반영한다. 같은 흐름과 Undo→Redo, 키보드 Undo→버튼 Redo 모두 통과했다.
2. **슬라이드 잘라내기가 복사만 하고 원본을 남김.** 썸네일을 선택하고 Ctrl/Cmd+X를 누르면 삭제 분기가 개체 선택에만 적용되어 장 수가 그대로였다. 키보드·Home·네이티브 cut 이벤트가 같은 슬라이드 잘라내기 경로를 사용하도록 수정했다. 같은 문서로 이동할 때 슬라이드 ID를 유지하여 기존 내부 링크를 보존하고, 여러 장 이동·노트 보존·Undo/Redo·마지막 슬라이드 보호를 확인했다.
3. **편집기가 저장 가능한 문서 한도를 넘겨 추가함.** 500장에서 새 슬라이드를 추가하면 501장, 개체 1,000개에서 도형을 추가하면 1,001개가 되어 자동 저장은 되지만 저장/재열기 검증이 실패했다. 추가·복제·붙여넣기·레이아웃·바닥글·이미지/영상·판서 보관에 공통 500장/장당1,000개/문서10,000개 제한을 적용했다. 1,000개에서 세 가지 추가 경로 거부 후 재열기로 기존 그림 보존, 문서 전체 개체 수 계산을 확인했다. 500장 상세 회귀는 large QA 담당의 `tests/large-document-limits.spec.ts`에 통합했다.

4. **네이티브 저장 직후 계속 입력한 텍스트의 실행 취소가 저장 시점까지 건너뜀.** `Alpha Beta`를 `First`로 바꾸고 네이티브 Save 명령→` Again` 추가→텍스트 편집 종료→Undo를 하면 `First`가 아니라 `Alpha Beta`로 돌아왔다. 저장이 문서 이력 트랜잭션을 종료했지만 텍스트 편집기는 열린 상태였고 후속 입력이 새 트랜잭션을 시작하지 않았다. 후속 텍스트 입력에서 새 트랜잭션을 시작하도록 수정하여 저장 성공·취소 양쪽에서 `First`로 Undo, `First Again`으로 Redo되는 것을 확인했다. 실제 저장창 대신 테스트 네이티브 브리지 응답을 사용했으며 PPTX 직렬화와 편집/이력 코드는 실제 경로다. 노트에서 저장 후 계속 입력하는 별도 검사도 통과했다.

5. **Mac 발표자 보기 종료 직후 F5로 다시 시작하면 새 발표까지 종료됨.** 실제 Mac 패키지에서 `발표자 보기→발표 종료→F5`로 재현했다. macOS는 전체 화면 전환 완료보다 먼저 창 크기를 바꾼다. 기존 구현은 이전 발표의 종료 애니메이션에서 발생한 `leave-full-screen` 이벤트를 새 발표 종료로 처리했다. `electron/presentation-window.cjs`에서 요청을 완료 이벤트 순서대로 처리하고 최신 발표 상태를 유지한다. 이전 발표의 정상 종료 이벤트는 새 발표를 종료하지 않으며, 사용자가 직접 전체 화면을 종료한 경우에는 발표를 종료한다. 원래 전체 화면으로 편집하던 창의 상태도 보존한다.

## 추가로 정상 확인한 흐름

- 텍스트+도형 묶기→복제→10px 이동→삭제→3회 Undo→3회 Redo.
- Undo한 뒤 다른 개체를 편집하면 이전 Redo 분기 제거.
- 부분 선택 기울임/굵게/밑줄, 한글·문단·색상 보존, PPTX 왕복.
- 우클릭 선택 유지, 복사·붙여넣기·잠금·앞뒤 배치와 실행 취소.
- 텍스트·도형·이미지 숫자 입력(너비200, 높이200, 회전−15), 음수·소수·Tab 확정·Escape 취소.

- 최종 테스트는 브라우저의 입력 묶음 시간 차이를 피하려고 단일 텍스트 입력 이벤트로 첫 Undo/Redo 단위를 고정한다. 초기 순차 키 입력 재현에서도 버튼 비활성화가 확인되었다. 용량 검사 도형 좌표 중복 때문에 생긴 테스트 클릭 실패는 샘플 배치를 수정한 뒤 재검증했으며 앱 버그로 집계하지 않았다.

## Mac 발표 전환 재검증 — 2026-10-23 KST

- `tests/native-presentation-transition.spec.ts` 5개 통과: 최초 진입 완료 전 종료, 종료 중 재시작, 최초 진입 중 종료/재시작, 기존 전체 화면 보존, 실제 사용자 전체 화면 종료. 기존 브라우저 전체 화면 검사 3개도 통과했으며 Windows 네이티브 1개는 Mac에서 제외했다.
- 수정 전 실제 이벤트: 전체 화면 진입 요청(0ms), 종료 요청(299ms), 첫 진입 완료(613ms), 재시작 요청(720ms), 이전 종료 완료(1168ms), 잘못된 렌더러 `presentation-ended` 1회, 새 진입 완료(1767ms). 수정 후에는 이전 진입·종료가 완료된 뒤 다음 요청을 보내며 잘못된 종료 알림은 0회였다.
- 실제 Mac ARM64 패키지에서 발표자 창→종료→F5, 2560×1440 전체 화면, 형광펜, 판서 보관→Undo/Redo→재열기까지 통과했다. 네이티브 `enter-full-screen` 완료를 확인한 뒤 판서 좌표를 계산한다. 발표 종료/재시작은 계속 즉시 실행한다.
- 저장/재열기·PDF→현재 릴리스 편집→숫자/글머리표→발표/판서를 한 프로세스에서 연속 실행한 전체 패키지 검사도 통과했다. 근거: `.cache/qa-user-editing/fullscreen-aggregate-after/`; 간결한 전후 이벤트 비교는 `qa/results/user-workflows/native-fullscreen.json`.

재현 가능한 명령:

```sh
npx playwright test tests/native-presentation-transition.spec.ts tests/presentation-fullscreen.spec.ts --output=.cache/qa-user-editing/fullscreen-regressions
node scripts/qa-user-workflows.cjs '/path/Slide Studio.app/Contents/MacOS/Slide Studio' .cache/qa-user-workflows-native
```

검사 도구에서 발견한 별도 문제: Electron의 `window.confirm()`을 Playwright CDP `dialog.accept()`로 수락하면 렌더러는 진행하지만 macOS 부모 창이 비활성 상태로 남아 전체 화면 진입이 무시된다. 새 프로필에서 단독 confirm 한 번으로 재현하여 앱 편집 결함과 구분했다. 패키지 연속 검사는 생성한 QA 자료를 교체하는 정확한 경고 문구만 제어하고 횟수를 기록하며, 예상하지 않은 대화상자는 실패 처리한다. 실제 확인/취소 보호 동작은 문서 보호 검사에서 별도로 검증한다. 앱의 창을 강제로 활성화하는 우회 수정은 하지 않았다.
