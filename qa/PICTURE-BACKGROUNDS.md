# 레이아웃·마스터 그림 배경 보존

다음 배포용 소스 변경. 공개 설치 파일과 리토스 공유 문서는 변경하지 않는다.

사용자가 같은 IXPE PPTX를 LibreOffice와 Slide Studio에서 열어 첫 장이 다른 것을 확인했다. 실제 두 앱 화면과 원본 XML을 비교했으며, `ppt/slideLayouts/slideLayout1.xml`의 `p:bgPr/a:blipFill` 그림이 Slide Studio에서 단색으로 대체되는 것이 원인이었다. LibreOffice의 제목·본문 입력 안내 문구는 빈 자리표시자 UI이며 실제 텍스트가 아니다.

그림 배경을 슬라이드의 별도 속성으로 보관한다. 배경을 소유한 슬라이드·레이아웃·마스터의 관계 파일에서 내장 이미지를 읽으며, 슬라이드에 지정한 배경이 상속 배경보다 우선한다. 동일한 관계 ID가 서로 다른 원본 파일에 있어도 혼동하지 않는다. 자르기·불투명도와 원본 이미지 바이트를 보존한다. 편집·미리보기·발표·인쇄에서 같은 배경 컴포넌트를 사용하고, 기존 GIF 정지 미리보기/발표 재생 동작을 따른다.

PPTX 저장 시 이미지 파일과 관계를 기록하고 네이티브 `p:bgPr/a:blipFill`로 옮긴다. 배경 그림을 일반 편집 개체나 전체 슬라이드 스크린샷으로 만들지 않는다. 외부 URL은 읽지 않으며 이미지 크기·전체 자산 합계·자르기와 불투명도를 검증한다. 타일·오프셋 배치와 지원하지 않는 형식은 기존 가져오기 안내에 남긴다. 단색 배경 선택은 그림/그라데이션을 해제하고, 모두 적용은 현재 그림 배경도 함께 복사한다.

신규 검사 5개와 관련 입출력·마스터 상속·0 크기 도형·색·발표 격리·판서·저장 모음까지 총 36개가 통과했다. 프로덕션 빌드도 통과했다. 신규 검사는 세 상속 위치의 관계 ID 충돌, 단색 슬라이드의 덮어쓰기, 내부 저장과 PPTX 3회 저장·재가져오기, 네이티브 배경 XML과 일반 그림 개체가 추가되지 않는 것, 외부 데이터/잘못된 자르기/불투명도 거부, 실제 렌더링 픽셀과 앞쪽 도형 표시, 배경 교체·실행 취소·모두 적용을 확인한다.

공개 샘플 5개도 가져오기·화면 렌더링·PPTX 저장·재가져오기에 성공했다. 슬라이드·개체 수와 0 크기 도형을 유지했고 모든 그림 배경의 데이터·자르기·불투명도가 보존됐다. IXPE 첫 장은 배경이 복원되어 기존 배경 대체 경고가 사라졌으며 LibreOffice의 같은 원본 화면과 배경·로고 배치를 시각적으로 비교했다.

로컬 증거는 `qa/results/background-images/`와 `qa/results/background-images-*.log`에 있다. 원본 다운로드 파일은 변경하지 않는다. Windows/Linux 설치판의 직접 실행 검증은 별도다.
