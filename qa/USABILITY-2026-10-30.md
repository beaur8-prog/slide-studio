# PowerPoint 사용성 비교 후 개선 — 2026-10-30

검수 시작 소스는 `19314fa`(패키지 1.6.15), 기존 설치 앱은 1.6.14였다. PowerPoint 공개 사용법과 실제 편집 시나리오를 비교해 아래 6개 항목을 재현하고 수정했다. 공개 릴리스·설치 파일·리토스 문서는 이번 작업에서 갱신하지 않는다.

선택 창 이름·숨김은 표준 PresentationML `cNvPr@name`, `cNvPr@hidden`을 사용한다. 이름의 중복을 허용하며, 비대칭 테두리의 소유자를 추적하는 내부 키와 표시 이름을 분리했다. 상위 그룹을 표시해도 개별적으로 숨겼던 자식은 계속 숨겨진다.

추가 검사에서 외부 편집기가 자동 이름을 바꾸고 Studio 확장 정보를 유지할 때 새 이름이 무시되는 문제도 재현했다. 표준 `cNvPr@name`이 내부 키와 달라지면 파일의 새 이름을 우선하도록 수정했다. 개체·그룹 이름 변경과 예전 확장 메타데이터가 있는 파일을 실제 PPTX XML 수정 후 가져오기로 검사했다. Microsoft PowerPoint 앱 자체를 이번 Mac 세션에서 실행한 검사는 아니다.

## 후속 개선: 차트 데이터 편집과 대용량 문서

작업 재개 후에는 새 차트가 개별 도형으로 만들어져 숫자를 다시 수정할 수 없던 흐름과, 보이지 않는 축소판·인쇄 화면까지 모두 만드는 비용을 개선했다. 공개 배포는 이번에도 진행하지 않는다.

새 세로/가로 막대·꺾은선·원형 차트는 표준 DrawingML 차트와 내장 XLSX 통합 문서로 만든다. 더블클릭, 선택 후 Enter, 우클릭 메뉴와 개체 서식에서 데이터 편집을 연다. 숫자·제목·종류·색상 변경은 적용할 때 한 번의 이력으로 반영하고, 취소·변경 없는 적용은 이력을 추가하지 않는다. CSV와 탭 구분 입력, 단일 계열 최대 12항목을 지원한다. 원형의 음수·합계 0과 잘못된 데이터는 적용하지 못하며, 미리보기 생성 중 취소한 작업이 나중에 반영되지 않도록 보호한다.

차트 삽입·수정 때에는 다른 그림·배경·동영상·차트가 차지한 용량을 합산하고 기존 차트 교체분은 제외한다. 첨부 데이터 합계 100 MiB를 넘는 변경은 편집 창에서 안내하고 적용하지 않아 저장할 수 없는 상태를 만들지 않는다.

차트는 PPTX를 저장하고 다시 열어도 편집할 수 있다. 4종 차트의 3회 왕복에서 값·한글 제목·그룹·이름·위치·회전과 실제 XLSX 셀을 확인했다. 원본 데이터의 별도 사본을 확장 정보에 보관하지 않고 표준 차트 캐시를 읽으므로 외부에서 값을 바꾼 뒤 이전 숫자가 되살아나지 않는다. 외부 값 변경은 XML 수정으로 검증했으며 Microsoft PowerPoint 앱을 직접 실행한 검사는 아니다. 외부에서 만든 차트, 지원 범위를 벗어나 계열이 추가된 차트, 외부 링크가 있는 차트는 원본 패키지 보존을 유지한다. 외부 Excel 파일과 실시간 연동하거나 예전 도형 차트를 자동 변환하는 기능은 아니다.

축소판과 전체 슬라이드 보기에서는 모든 슬라이드의 버튼·접근성 이름·선택·드래그 영역을 유지하고, 보이는 범위와 주변 400px의 그림만 렌더링한다. 현재 슬라이드는 즉시 표시한다. 전체 인쇄 화면은 `beforeprint`에서 동기적으로 만들고 글꼴·그림 디코딩을 기다린다. 정상 출력·취소·오류 후에는 제거한다. 브라우저 인쇄도 같은 이벤트를 사용하며 출력에서 편집 대화상자를 제외한다.

PPTX 가져오기·저장·개체 삽입의 검증은 전체 문서를 JSON으로 복제하는 대신 같은 필드 검증기에 객체를 전달한다. 문자열 이스케이프를 포함한 JSON 길이를 계산하여 200 MiB 제한을 유지한다. 허용된 200MB 가까운 텍스트 문서와 이를 넘는 문서, 줄바꿈으로 직렬화 크기가 커지는 문서, 중복 ID·잘못된 좌표·이미지·개체 종류·ZIP/XML 경계를 검사했다.

### 300장 혼합 문서 비교

같은 37,182,813바이트 파일과 같은 Mac/Chrome에서 처음 열기, 처음·끝·중간 이동, 10자 입력, 실행 취소·다시 실행, 실제 PPTX 저장·재열기를 수행했다. 텍스트·노트·표 내용과 그림 원본의 SHA-256을 보존했다. 개선 뒤에는 추가로 두 번 재열기했다. 측정값은 하드웨어와 부하에 따라 달라지며 완전한 무중단 처리를 뜻하지 않는다.

| 항목 | 변경 전 | 변경 후 |
|---|---:|---:|
| 열기와 자동 저장 | 3,719.8ms | 2,598.7ms |
| PPTX 저장 | 3,553.9ms | 3,233.1ms |
| 재열기와 자동 저장 | 3,688.6ms | 2,915.7ms |
| 열기 뒤 CDP Nodes | 100,820 | 35,402 |
| 열기 뒤 JS 힙 | 80.4MiB | 66.7MiB |

개선 뒤 실제 문서 DOM은 3,443개, 축소판 8개, 편집 중 인쇄 슬라이드 0개였다. CDP Nodes에는 분리된 노드도 포함되어 실제 문서 DOM 수와 다르다. 추가 재열기 뒤 힙은 108.7 → 108.8 → 108.8MiB로 유지됐다. 변경 전 재열기의 84.6MiB보다 높으므로 모든 단계에서 메모리가 감소했다고 볼 수 없다. 반복 횟수 전체에서 최대 941ms의 메인 스레드 작업이 남았다.

### 후속 검증

- 후속 전체 회귀 검사: **452개 통과, 19개 제외, 실패·재시도 성공 0개**(16.4분). 그 뒤 추가한 차트 첨부 용량 보호와 그림·축소판·출력 경로 관련 **20개 검사를 모두 통과**했다(48.7초). 두 집계는 중복되므로 합산하지 않는다. 최종 용량 보호 추가 후 471개 전체를 다시 실행했다는 의미는 아니다.
- 최종 패키지의 `qa-chart-print.cjs` 6개 흐름: 차트 삽입·편집·Undo/Redo, 네이티브 저장·재열기, 실제 PDF, 인쇄 성공·취소·실패 뒤 임시 DOM 해제. 인쇄 콜백만 별도 테스트 프로세스에서 대체했으며 실제 프린터 출력은 하지 않았다.
- 같은 패키지의 기존 `qa-usability.cjs` 6개 흐름도 다시 통과했다. 두 검사 모두 사용자 프로필과 분리했다.
- 최종 PPTX 구조 검사와 3쪽·27쪽 PDF 페이지 수·한글 텍스트 추출을 확인했다. 27쪽을 렌더링해 확인했고, 객체 검증 변경 전후 3쪽 차트 PDF의 렌더링 픽셀은 같았다.
- 고정된 해시의 공개 실무형 3개 문서·34장도 저장 왕복을 다시 통과했다. 자동 잘림·겹침 후보와 JavaScript 오류는 0개였다.
- 업데이트 로직 17개, Windows 설치 스크립트 컴파일과 Linux DEB 구성 검사도 통과했다. Windows/Linux 네이티브 앱 실행을 뜻하지 않는다.

```sh
node scripts/qa-chart-print.cjs '/path/Slide Studio.app/Contents/MacOS/Slide Studio'
QA_LARGE_REOPEN=2 node scripts/qa-large-workflow.cjs qa/results/usability-continuation/performance-final generated
```

후속 코드로 만든 Mac 1.6.15 로컬 앱도 `/Applications/Slide Studio.app`에 교체했다. 패키지의 57개 파일이 빌드 결과와 일치하고 ASAR SHA-256은 `c8af2a89cb679fa598cf7aa216d73a8c4f86c9e899cab82161c2a739a2868e3c`이다. 초기 제목 슬라이드·빈 노트·비활성 Undo/Redo와 대화상자가 없는 상태를 다시 확인하고 정상 종료한 뒤 교체했다. 재실행 후 같은 초기 화면과 저장 완료를 실제 macOS UI로 확인했다. 공개 설치 파일과 리토스 문서는 변경하지 않았다.
