# Word Studio의 Windows 업데이트 수정 선별 반영

- Slide Studio 개발 버전: **1.6.22**, 이전 **1.6.21**.
- 검토 원본: Word Studio `522959c4bc5c9f80b55464df1c80934806a9b596`, `39be35ef30e586c66e5aa5a27442a43de99d3336`, 최종 시험 기록 `1c00fd72bdc36c6c88e786c709798027a3cd2631`의 1.4.13 변경.
- Word의 실제 Windows 시험은 1.4.12→1.4.13, 사용자별/전체 사용자/기존 중복 설치 정리에서 통과했습니다. 이 수치를 Slide Studio 검증 결과로 대신 사용하지 않습니다.

## 반영한 동작

Windows 도우미가 준비 응답을 보내기 전에 실행 중인 Slide Studio의 경로를 현재 사용자의 기본 설치 폴더 및 64비트 HKCU 설치 등록과 대조합니다. 제품 이름, 설치 위치, 인용된 제거 명령, 실행 파일·제거 파일·설치 표식의 존재를 확인합니다. 복사된 앱 폴더나 등록이 맞지 않는 설치본은 종료시키지 않고 로그와 수동 Setup 경로를 안내합니다. 해당 진단을 시작 시간 초과 오류로 덮어쓰지 않습니다.

검증한 폴더를 NSIS의 마지막 `/D` 인자로 명시합니다. Word의 수정처럼 설치 프로세스 핸들을 먼저 유지하고 완료 후 새로 읽어, PowerShell 5.1에서 종료 코드를 정확히 확인합니다. 설치 후 원래 실행 파일 버전뿐 아니라 설치 등록의 버전과 설치 표식까지 새 버전인지 검사합니다.

Slide Studio는 현재 사용자 기본 폴더 전용 설치 프로그램입니다. Word의 전체 사용자·사용자 지정 경로 지원을 옮기지 않습니다. 자동 설치는 기존 `/S` 방식과 다섯 단계의 별도 진행 창을 유지하고, 설치 완료 화면이 앱을 추가 실행하지 않습니다. 기존 단일 인스턴스 처리, 문서 저장·정상 종료·종료 취소, Mac/Linux 수동 업데이트를 유지합니다. 공개 릴리스와 리토스 문서는 변경하지 않습니다.

## 검증

- 로컬 업데이트 Node 검사 **31개 통과**. 설치 등록 거부 시 앱 유지, 구체적인 오류·로그·수동 설치 안내를 추가로 확인했습니다.
- `npm run build` 통과. 기존 Vite 청크 크기 안내는 남아 있습니다.
- 관련 UI·문서 보호 검사 **21개 통과**. 업데이트 메뉴·다운로드 단계·취소·저장 실패·미저장 작업 보호와 세 플랫폼 버전 표시를 확인했습니다.
- Mac 1.6.22 패키지 빌드와 임시 서명 검증 통과. 두 업데이트 파일을 app.asar에서 추출해 소스와 같은 바이트임을 확인했습니다.
- 실제 Windows 설치본 판별 **10개 통과**, 실제 Electron·PowerShell 도우미 **6개 시나리오 통과**. 정상 설치·종료 취소·실행 차단·도우미 변조·미등록·기본 폴더 밖의 복사본을 확인했습니다. 거부되는 설치본은 편집기를 닫거나 설치하지 않았습니다.
- Mac에서 저장된 기본 제목 슬라이드와 열린 대화상자 없음을 확인하고 정상 종료한 뒤, 이전 앱을 백업하고 `/Applications/Slide Studio.app`을 1.6.22로 교체·실행했습니다. 상단의 1.6.22 표시를 실제 UI로 확인했습니다. 사용자 자료 폴더는 교체하지 않았습니다.
- [최종 Windows CI](https://github.com/beaur8-prog/slide-studio/actions/runs/41257615641), 구현 커밋 `9d4d6be1d7a48c77d6cafabacca0f99eec9221c0`: **전체 통과**. Windows에서도 업데이트 검사 31개·관련 UI 21개가 통과했습니다. 실제 공개 **1.6.21 → 1.6.22** Setup 교체, 다섯 단계의 진행 창, 원래 설치 위치·등록·표식·바탕화면 바로가기 대상, 편집기 주 프로세스 **1개**, 재실행과 프로필 표식 자료 보존을 확인했습니다.

Windows 시험에는 생산 코드의 대상 판별 함수를 실제 레지스트리/파일로 호출하는 검사, 실제 Electron·PowerShell의 준비 응답/취소/실행 차단/도우미 변조/미등록/복사 경로 검사, SHA-256을 확인한 현재 공개 Setup에서 새 버전으로 바꾸는 시험을 포함합니다. 실제 교체에서는 설치 위치·등록·설치 표식·바탕화면 바로가기 대상·편집기 주 프로세스 한 개·사용자 자료 보존을 확인합니다. 시험은 기존 설치가 없는 격리 Windows CI에서만 실행합니다.

구버전 교체 시험은 실제 두 버전의 Setup과 새 PowerShell 도우미를 사용하되, 종료 대기 대상은 짧게 실행하는 시험용 프로세스입니다. 구버전 앱 내부의 업데이트 버튼부터 전 과정을 실행한 시험은 아닙니다. 실제 Electron의 정상 종료·취소는 별도의 도우미 연결 시험에서 확인하며, 자료 보존은 격리 프로필의 표식 파일로 확인합니다.

첫 CI 실행은 정리된 1.6.16 릴리스를 요청해 기준 설치 파일 다운로드에서 중단됐습니다. 앱 검사와 설치본 판별·도우미 시험은 통과했으며, 기준 파일은 현재 공개 릴리스의 정확한 태그와 SHA-256을 읽어 고정하도록 수정했습니다. 현재 공개 버전은 1.6.21입니다.

실제 Windows 오류 안내 원문에서 PowerShell이 결과 로그를 쓰는 동안 Node가 `EBUSY`를 받는 경우를 발견했습니다. 준비 응답을 기다리는 제한 시간 안에서 해당 잠금만 다시 읽도록 수정했고, 원래 설치 등록 거부 이유가 유지되는 회귀 검사와 네이티브 오류 문구 검사를 추가했습니다.

마지막 Windows 로그 잠금 보완을 포함한 Mac 패키지도 다시 빌드·서명 검증했고 두 업데이트 파일의 소스 일치를 확인했습니다. 그사이 Mac이 잠겨 현재 실행 중인 1.6.22 앱(첫 구현 `64b5f6c`)은 유지했습니다. 마지막 보완본(`9d4d6be`)으로의 Mac 재교체는 잠금 해제 후 진행해야 합니다. 이전 1.6.21 앱은 `~/Library/Application Support/Slide Studio Backups/windows-update-1.6.22-20261101/`에 보존합니다.
