### 오디오 구현 범위

내장 MP3·PCM WAV·AAC M4A(각 20 MiB), 삽입·미리 듣기·자동/클릭 시작·반복·볼륨·음소거·여러 슬라이드 연속 재생을 구현하고 있습니다. 편집 썸네일과 인쇄는 정지 아이콘이며, 발표자 보기에 중복 플레이어를 만들지 않습니다. 앱 발표에서 아이콘을 숨기는 설정은 앱 확장 메타데이터에 저장합니다. PowerPoint의 녹음·트리밍·복잡한 타이밍 전체를 지원한다는 뜻은 아닙니다.

표준 오디오 파일 연결과 `p:audio/cMediaNode`의 볼륨·반복·슬라이드 수는 [Microsoft Open XML 오디오 설명](https://learn.microsoft.com/en-us/office/open-xml/presentation/how-to-add-an-audio-to-a-slide-in-a-presentation)과 [CommonMediaNode 명세](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.presentation.commonmedianode?view=openxml-3.0.1)를 기준으로 확인합니다. PptxGenJS가 audio에도 videoFile을 쓰는 부분은 저장 후 표준 audioFile로 교정합니다.

최종 Mac 번들에서도 151장 자료의 복구 저장과 세 번 재열기 후 한글 노트·원본 ZIP 데이터 해시가 일치했습니다. 무결성 검사가 문서를 별도로 복제하면서 메모리 관측을 왜곡하지 않도록 검사 순서를 분리했습니다. 실제 UI 재열기 후 강제 GC한 JS 힙은 약 141/139/139 MiB였습니다. 프로세스 working set 합계는 약 1016/1027/1013 MiB로 안정됐으나, **렌더러 피크는 약 1599 MiB**였습니다. working set 합계에는 공유 영역이 중복될 수 있으며, JS 힙만으로 실제 앱 RAM이 139 MiB라고 주장하지 않습니다. 큰 파일을 여는 순간의 메모리 감소는 남은 개선 과제입니다.

LibreOffice를 사용자 창과 분리한 임시 프로필로 실행해 한글 조직도 원본과 3회 저장본을 PDF로 비교했습니다. 최초 환경은 원본의 한글도 누락하므로 시스템 글꼴 경로를 임시 프로세스에만 지정해 다시 검사했습니다. **22장 중 21장의 96dpi 렌더 PNG가 SHA-256 기준으로 동일**했고 조직도 6쪽도 한글 8개 항목과 배치가 같습니다. 12쪽 표는 아래 경계가 약 2px 달랐으며 내용 누락은 보이지 않았습니다. 이는 LibreOffice 교차 검증이며 Microsoft PowerPoint 앱 직접 실행 결과는 아닙니다. 공개 강의의 PowerPoint 생성 PDF 대표 쪽도 대조했으며 원본 light 글꼴의 두께 차이는 남아 있습니다.

최종 소스의 Mac ZIP·Windows Setup·Linux DEB 검수 후보를 만들었습니다. 세 패키지의 `app.asar` 해시가 일치하고 `dist`·`electron` 61개 파일이 소스와 같습니다. 서명/공증 상태는 바뀌지 않았고 공개 다운로드 파일·리토스 문서는 갱신하지 않았습니다. [소스에서 설치·재설치·제거하는 검사](https://github.com/beaur8-prog/slide-studio/actions/runs/41120786630)는 임시 Windows·Ubuntu 22.04/24.04에서 진행하며, 설치 파일을 게시하지 않습니다. Mac은 잠금 때문에 사용자 설치 앱의 미저장 문서 확인과 교체가 아직 남아 있습니다.
