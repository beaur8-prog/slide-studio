## Git 반영과 로컬 앱

수정 소스와 자동 검수 기록은 `9d5fce8`로 `origin/main`에 반영했다. 검증한 앱을 `/Applications/Slide Studio.app`에 설치하고 서명·ASAR 일치를 확인했다. 이후 실제 macOS UI에서 노트 입력 → 새 문서 만들기 → 미저장 경고의 Cancel → 노트 유지 → 전체 화면 발표 → Escape → 상단 Undo로 원래 빈 노트 복원을 확인했다. 정상 종료 후 다시 실행하여 기본 제목 슬라이드 1장, 빈 노트, 비활성 Undo/Redo 상태로 남겼다. 이 수동 검사에서는 Playwright의 확인창 가로채기를 사용하지 않았다. 공개 릴리스 버전은 이 검수 작업에서 갱신하지 않았다.

## 범위와 남은 한계

- Mac ARM64의 Chrome/Electron에서 검수했다. 네이티브 파일 선택 응답은 테스트에서 지정했지만 실제 IPC, 디스크 PPTX/PDF 쓰기와 읽기를 수행했다. OS 파일 선택 창을 사람이 직접 조작한 검사와 구분한다.
- Windows/Linux 설치 앱을 이번 검수에서 실행하지 않았다. Windows 전용 전체 화면 시험과 로컬에 없는 Arial Nova Light 시험은 건너뛴다.
- 한글 입력은 Chromium 조합 이벤트와 실제 문자열 편집으로 확인했다. 모든 운영체제의 실제 한글 입력기 전환까지 확인한 것은 아니다.
- 큰 PPTX 생성은 여전히 메인 스레드를 사용한다. 약192MiB 파일은 열기 3.41초, 저장 7.07초, 다시 열기 4.05초였고, 저장 중 최대 3.17초의 메인 스레드 작업이 관찰됐다. 이 응답 지연은 남아 있다. 데이터 손실과 실행 오류는 없었고 세 차례 반복 열기의 메모리는 안정적이었으나, 저장 처리를 별도 작업자로 분리하는 성능 개선과 저사양PC 확인은 후속 과제다.
- 모든 슬라이드가 Microsoft PowerPoint와 픽셀 단위로 일치한다고 보증하는 검수는 아니다.
